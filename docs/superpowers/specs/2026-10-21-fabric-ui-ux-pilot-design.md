# Fabric UI/UX 第一批样板设计（2026-10-21）

## 目标与现状
当前 Fabric 已有 fabric-ui-design、frontend-design、web-design-guidelines，新增 ui-ux-pro-max。原有 React 组件和局部 Edge CDP 脚本未构成跨页面一致、强制可复现的 UX 门禁。用户明确要求先装技能、建立新工作流，并用色卡库体验建立第一批样板。

## 方案
采用**不改正式业务路由的可交互样板**，新增本地评审页 `?view=cardUx`。直接使用现有 React、Tailwind、隔离演示数据，基于 Radix Dialog 实现焦点恢复、Escape、遮罩关闭。展示色卡搜索（编号、花型、面料），行操作“查看花型”“分享预览”“查看二维码”。分享仅提供本机演示链接，**不得伪称生产可用或向真实客户分享**；真实分享 API、产品资料、权限、扫码及生产发布由后续专项验收。

## 体验约束
- 搜索条件变化实时过滤并提供结果计数；零结果明确反馈、可一键清除；不可出现旧搜索残影。
- 色卡编号、面料、花型母版的身份清晰；查看花型强调该卡下的配色；分享预览强调该卡的多款产品与三类媒体展示职责。
- 所有行操作是具名按钮；弹窗有标题、关闭、Tab 焦点循环、Esc、关闭焦点还原；二维码只是演示，不编码生产色卡私密 token。
- 保留表格滚动、桌面 1440 与手机 360 视口；示例图明确“占位预览”，不伪造真实产品图。
- 样板使用本地固定模拟数据，不访问生产 API/MySQL/COS；样板的“复制”只能复制本机预览网址。

## 质量关卡
每个 UI 任务需要：前后状态/任务流的短说明、设计规范来源、受影响组件、至少一条有真实浏览器证据的主路径、取消/错误/空态和键盘路径、必要窄屏检查。以 Playwright 在独立 Vite 评审入口自动运行，用 Edge 本机浏览器；测试不接服务器正式后端。旧页面不因样板自动合入/发布。

## 不包含
不触碰正式 App 路由、生产接口和数据库，不创建公开可用的分享 URL，不改旧二维码协议，不批量重构色卡库或统一全部主题。
