# P2 登录、权限与成员管理技术说明

用途：V2认证与权限接线。**现行角色规则以[项目需求总览2.1](../project/项目需求总览.md#roles)优先**，阶段状态见[进度](product-master-v2-progress.md)；早期授权设计见[历史规格10.1](product-master-v2-requirements.md)。旧路由切换见[切流约束](README.md)。2026-10-15本机已按简化角色规则更新部分服务端代码，不代表线上已启用。

## 身份和权限

- `server/access/policy.ts`按当前确认规则：有效登录admin与sales均可维护三库、共享标签、导出产品、导入重复面料（预览差异并二次确认）和创建单据；sales只可查看/修改本人单据。**仅新增账号、主动手工开单仍为admin专属。** 旧`canManageOwnOrders/canManageProducts`字段仍保留在V2数据结构、成员管理存储及部分旧UI中作兼容，**不再决定两角色的正常业务授权**；不要重新引入额外双授权。
- `password.ts`使用加盐scrypt及随机32字节会话令牌；用户/会话表存密码散列与token的SHA-256摘要、到期及撤销信息，不存原始凭据。
- `routes.ts`独立POST login、GET me、POST logout，标准化用户名，错误登录限流与统一反馈、未知用户等价散列验证；`middleware.ts/sessions.ts`每请求实时查当前用户/会话。
- `members.ts/memberRoutes.ts`事务内锁定有效执行者和目标；目前仍可存储旧授权列，后续需同步简化成员设置UI/DTO，避免展示已无业务作用的开关。停用或变角色撤销会话，重置密码与撤销同事务；最后管理员用行锁及有效管理员计数保护，业务员不能管理成员。
- 所有订单出入口使用同一owner规则；销售看他人/NULL owner统一404，管理员可读历史。401身份失效、403缺动作权限、404隐藏对象存在性、503安全服务错误；真实写入还需事务内重新核验，不能只依赖前置中间件。

**2026-10-15本机专项更新**：`policy/sessions/routes`、三库及独立统一HTTP服务的角色判断已按新规则TDD回归：不再依赖旧两个授权位；未登录、停用/撤销账号、跨owner单据、引用及并发保护仍拒绝。面料导入允许任一角色选择冲突更新，但必须服务端重查当前账号、预览token、原始行指纹与锁。**本轮代码质量全量通过，但尚未在真实账号+真实MySQL/正式App中验收。**
