## 1. 文档口径

本文供业务负责人逐项审查，作为后续设计和实施计划的输入。内容分为三种状态：

- **基线**：已从历史讨论恢复，或由用户在本轮明确提出的要求；仍可在本次评审中修订。
- **评审建议**：为补齐流程提出的具体方案，尚未视为用户已批准。
- **待细化**：目标已经明确，但缺少决定实施范围所需的业务规则。

字段、图片、编号等核心基线集中于第 4～7 节；需作出决定的事项集中于第 14 节。文档批准后形成冻结版本，具体实现与接口契约另行设计。

## 2. 业务目标与范围

### 2.1 业务目标【基线】

建立花型库、面料库和产品库，支撑以下业务：

### 2.2 当前业务前提【基线】

1. 新产品库从空库开始使用，后续人工录入和维护。
2. 不要求历史产品数据导入、迁移、正确性校验或与历史工作簿比对。
3. 花型、面料和产品分开管理，产品通过关联读取主数据。
4. 图片处理与存储复用现有图片资产能力。
5. AI 效果图由人员在系统外制作，系统管理结果图片。
6. **2026-10-12 新确认**：旧版产品库不再需要，原产品库数据及仅用于旧产品域的关联记录、旧入口、旧导入功能允许清理/淘汰；V2 以全新结构和空产品数据正式使用，**不做旧产品库结构/API兼容**。具体清理时必须识别外键与图片引用，不将此许可扩大到历史样布码单、定金单、销售发货码单、客户/库存/公司资料或共用图片资产；旧单据原明细和保存信息仍按第9.3节保留。当前未执行任何数据库删除。

“不做历史数据正确性校验”不取消录入时必要的编号唯一性、图片数量和安全限制，也不取消系统功能验证。

## 4. 三库关系与字段

### 4.1 关系【本轮确认】

> 业务负责人已明确确认（2026-10-09）：配色归花型库，同一母花型下有多个配色版本；具体配色版本与面料唯一确定产品，不同配色应用于同一面料是独立产品。此次确认仅针对该关系模型，不代表整份评审稿或其他建议已获批准。

```text
一个花型母版 ── 多个花型配色版本
                       │
                       └── 与不同面料组合形成产品

一条产品 = 一个具体花型配色版本 + 一种面料
```

同一母花型的配色1和配色2应用到同一种面料时，是两个独立产品，可以分别选款、开单。这里“花型 + 面料唯一确定产品”中的花型，指已确定配色的具体版本，而不是未区分配色的母版。

配色属于花型库：数字配色序号、该版本原图、备注与状态均在花型库维护；题材和颜色标签在花型级统一维护。不要求准确选定一种身份颜色，不维护必填配色名称，也不按颜色词映射编号。产品只关联一个具体配色版本与一个面料；同一母版内两个实际配色即使标签完全相同，也可以用不同序号区分。

仍然只有花型库、面料库、产品库三个业务入口；花型母版及配色版本是花型库内部的两层资料，不新增第四个独立业务库。逻辑对象由三种扩展为花型母版、花型配色版本、面料、产品，具体存储设计后续确认。

### 4.2 花型库：母版与配色版本字段【本轮确认】

花型母版维护编号、题材和颜色标签；每个配色版本维护数字身份、自己的原图、备注及状态。以下字段标识为需求逻辑标识，物理表与关联结构在技术设计阶段确定。

**花型母版**

| 业务字段 | 标识 | 含义与规则 |
| --- | --- | --- |
| 内部 ID | id | 系统关联标识，与业务编号区分 |
| 花型母版编号 | pattern_master_no（逻辑字段） | 母版唯一编号，例如 1234；与含配色序号的花型编号区分 |
| 图案题材标签 | topic_tags（逻辑字段） | 花型级多选，支持自定义标签值 |
| 颜色标签 | color_tags（逻辑字段） | 与题材同级，花型下配色共用；多选、支持自定义 |
| 启用状态 | is_active | 启用 / 停用 |
| 创建、更新时间 | created_at / updated_at | 系统维护 |

**花型配色版本**

| 业务字段 | 标识 | 含义与规则 |
| --- | --- | --- |
| 配色版本 ID | id | 内部稳定标识，供产品关联 |
| 所属母花型 | pattern_id | 一个版本属于一个母花型 |
| 花型编号 | pattern_no（逻辑字段） | 自动生成：母版编号 + “-” + 配色序号，例如 1234-1；唯一，不手工填写 |
| 配色序号 | colorway_no（逻辑字段） | 必填正整数，同一母版内唯一，如1、2；不表达颜色；分配方式见4.2.3已批准D-01规则 |
| 配色版本花型图 | pattern_image_asset_id | 每个配色版本独立维护一张花型原图的关联；暂无图时显示本版本待上传，不借用母版或其他配色的图。仍沿用先建版本后补图的可空规则 |
| 备注 | remark | 本版本补充说明 |
| 启用状态 | is_active | 版本可单独启用 / 停用；新业务同时遵守母版、版本、面料与产品启用限制，见第 7 节已批准规则 |
| 创建、更新时间 | created_at / updated_at | 系统维护 |

花型题材和颜色标签均归母版共用。配色版本不重复维护题材或颜色标签。可先创建母版，随后增加配色版本；产品必须选择一个具体版本才能确定身份。

**配色版本花型图归属【用户于 2026-10-10 再次明确】**：母版不维护一张供所有配色共用的花型图。1234-1 与 1234-2 各有自己的原图关联和预览 / 上传 / 替换 / 删除入口。新增配色不自动继承已有版本图片，数字配色编号不推断颜色、不自动给图片改色。替换或移除某版本的图，仅改变该版本的关联及引用它的产品当前展示，不修改其他配色版本；物理资产回收继续遵守共享引用规则，已有订单 / 画册治理仍按二期范围处理。

#### 4.2.1 花型多维标签【本轮确认】

标签目的为快速筛选到需要的花型。一期只设置两个维度，不设置风格和花型大小维度：

| 维度 | 含义 | 初始候选示例 | 录入方式 |
| --- | --- | --- | --- |
| 图案题材 | 原图描绘的图案内容 | 花卉、植物、条纹、格纹、几何、动物、佩斯利、波点、字母图文、肌理、其他 | 多选，可新建自定义值 |
| 颜色标签 | 花型级共用的颜色分类 | 蓝色、绿色、藏蓝、米白等；统一使用第 4.2.3 节共享颜色词表 | 多选，可新建自定义值 |

示例仅为初始候选，不是固定枚举。风格类的“度假、民族”等不再作为初始题材标签，不把已排除的风格或大小作为必填分类。

- 题材和颜色均归母花型，两个维度同级维护，不从产品实拍、效果图或面料自动推断。
- colorway_no 在配色版本维护，颜色标签在花型级维护；不维护身份颜色代码/配色名称，标签不决定序号。
- 同一花型的不同配色各有独立原图，共用花型题材和颜色标签；新增面料产品不改变花型标签。
- 两个维度分别维护，允许多选与暂不填写。更换某配色版本原图不自动改动花型颜色标签，用户可另行调整花型级标签，不新增自动识别或正确性审核要求。
- 产品需要标签资料时读取母花型的题材及颜色标签，不创建产品自己的另一套同名标签。
- topic_tags / color_tags 是业务逻辑字段名，物理存储与词表关联方式在技术设计时确定，不能仅照旧 category_tags 固定数组实现。

#### 4.2.2 自定义与词表维护

**已确认需求：** 两个维度均支持自定义标签值；用户能选择已有值，也能录入新值。自定义的是维度下的标签值，不自动扩展为自定义维度管理系统。

**首版标签规则【用户授权采用默认方案】：**

- 标签选择器按维度分组，支持搜索已有标签；没有合适值时在该维度新建，创建后可直接选中。
- 标签使用团队共享词表，其他人员可重复选择，不限于创建人使用。
- 标签名去首尾空格后为 1～32 个字符，空名称不可保存。同一维度按大小写不敏感、全半角规范化后的名称判重，重名复用现有值，不重复新建。
- 系统登记且有效登录的管理员和业务员均可新建、维护花型及标签，不依赖旧产品管理授权开关。
- 管理员和业务员均可维护共享标签的重命名、合并和归档；归档值不供新关联选择，既有关联与查询仍可追溯。权限规则已通过 R-20。
- 重命名影响所有关联花型，操作前应提示影响范围；已使用标签不直接物理删除。
- 每个花型题材标签为 0～10 个；颜色标签为 0～10 个，两维度分别计数。配色序号不属于颜色标签，不占标签名额。词表本身不设 10 个候选的总数限制。
- 数量上限后续可调整，但不得静默删除已有标签关联；新录入或修改超限时明确提示。

共享词表维护规则已批准，不新增业务正确性审核、图片识别服务或复杂自定义维度系统。

#### 4.2.3 数字配色标识与颜色标签【2026-10-12修订】

**已确认：** 花型母版下的配色使用数字标识。母版1234有两个配色时分别为1、2，完整花型编号为1234-1、1234-2。即使不能准确命名颜色或两版颜色标签相同，也可建立两个独立配色；无需先建立“蓝白”“蓝金”等身份颜色词条。只有一个配色也采用带数字的完整编号，不将母版直接作为可选产品花型。

配色通常为1～4种，但不设4个硬上限，允许第5及以后。列表按常见数量保持紧凑，例外通过横排溢出或续行承载，不限制保存，也不缩小图片到无法辨识。序号是版本标识，不是当前配色数量，也不表示颜色值；例如删除某版后有1234-1和1234-3，并不意味着当前仍有三个配色。

**系统编号规则【D-01 / 2026-10-12 用户已批准】：** 点击添加配色可预览所属母版预计的下一正整数序号；**只有正式保存成功**才由后端在该母版内从1起单调递增分配。保存成功后任何版本的配色序号永久只读，**无论是否已被产品引用都不能修改**；停用、删除、改变显示顺序均不重新编号、不复用已经成功分配过的序号，允许留下历史空缺。例如已有1、2、3，删除2之后新建应为4，而不是2。取消未保存草稿不消耗序号。并发提交由后端事务锁及唯一约束保证，每次成功只分配一次，客户端预览不承诺必然是最终号码；需要持久记录下一个号，**不得以当前现存版本数量或MAX(现存colorway_no)推断可复用号码**。本轮批准业务规则，不代表后端实现或真实验收完成。

**花型颜色标签【2026-10-16用户修订】：** 可选多选、自定义，与题材标签同级，在花型级维护和筛选，与配色序号独立。无法判断时可以留空，或人工选“多色”等合适标签；不要求主色、标准色号或精确颜色识别。初始候选保留红色、橙色、黄色、绿色、蓝色、藏蓝、紫色、粉色、棕色、黑色、白色、灰色、米色、米白、多色；不再附带RD/NV/IV/C0001等身份代码。共享词表治理及原0～10个、1～32字符规则保持，重命名或合并标签不改变花型或产品编号。

旧“花型颜色必填单选→固定字母代码→花型编号”方案及配色名称被本节替代；不能通过颜色标签反向生成身份。每版稳定ID、独立图片、备注、启用状态和引用约束继续保持。本轮修订需求和评审示例，产品库无历史数据，不新增正确性核验、历史导入或自动批量改号；已有实际单据保留原保存资料，应用存储结构在技术设计时确定。

### 4.5 编号名称、自动生成与唯一性【本轮确认】

| 名称 | 所属对象 | 生成 / 录入方式 | 示例 |

| 花型母版编号 | 花型母版 | 人工录入，共同设计的业务编号 | 1234 |

| 花型编号 | 具体配色版本 | 母版编号 + “-” + 配色序号，系统生成 | 1234-1、1234-2 |

原先用于共同设计的“花型编号”正式改称“花型母版编号”。本版“花型编号”专指已经确定配色的具体花型，不再用一个名称同时指母版和配色版本。

录入顺序：先建母版1234，再新增数字配色1，生成完整花型编号1234-1；产品选择1234-1与面料S23，生成货号1234-1-S23。用户不再为生成编号选择颜色；具体顺序分配、永久锁号及不复用按4.2.3已批准D-01规则。

**编号生成与约束：**

- 母版编号全库唯一；同一母版下数字配色序号唯一。不同母版可分别有配色1、2。
- 保存版本须有所属母版和有效正整数配色序号；空串、0、负数、小数和同母版重复序号无效。无需身份颜色或颜色映射。系统自动分配；所有已保存配色序号永久只读，不提供普通改号入口。
- 花型编号由系统生成，全库唯一；花型版本内部仍有稳定 ID，不能只靠编号字符串建立关联。
- 产品唯一组合仍是 (pattern_colorway_id, fabric_id)，产品编号也全库唯一；同一花型编号与同一面料品号不能重复建立产品。
- 同一母版不同配色配同一面料，得到不同花型编号和不同产品编号。
- 编号组成部分为母版编号、配色序号、面料品号。母版编号与面料品号执行去首尾空格、英文字母转大写、字母数字及禁止内部横杠规则，R-02 已批准；配色序号改为正整数，不使用字母或横杠；由系统生成的完整花型编号与产品编号允许且包含分隔横杠，不能对完整编号套用“禁止横杠”。
- 用户不手工输入生成后的花型编号或产品编号。前端实时预览，保存时由系统最终生成并检查唯一性。
- 重复组合提示现有花型版本或产品，不静默覆盖、不新建重复记录。
- 母版编号的修改会影响花型编号及关联产品编号；所有已保存配色序号永久只读，删除/停用不复用；面料品号修改会影响关联产品编号，已被引用时的锁定 / 更正规则见 R-07，不静默批量改号。

当前编号规则替代旧“母版编号-面料品号-配色序号”的顺序。编号变化不影响内部永久身份；二期花型稳定链接与实体色卡二维码各自关联母花型及色卡，**不需要单产品二维码**。

**业务要求【基线】**：独立维护品号、品名、成分、克重、门幅、备注和状态。

**页面方案【评审建议】**：列表显示完整面料资料与关联产品数，点击编辑进入行编辑；修改后明确保存或取消，不逐字符自动写入。

**面料 Excel 导入【R-03 已批准】**：一期保留面料成分表导入，字段包括品号、品名、成分、克重及单位、门幅、备注。规格可留空；管理员、业务员均可导入，重复记录均须二次确认；不扩展为历史产品校验、去重或迁移。

**重复品号处理**：管理员和业务员均可导入面料。导入前预览重复品号及新旧字段差异，操作者须二次确认选择跳过或更新；未确认不得执行重复项，不静默覆盖或跳过。两种角色按同一规则执行，不再限制只有管理员可更新。文件内重复组保护和空值保留规则仍适用。

**更新空值规则【S-01 已批准】**：导入人二次确认更新已有面料时，Excel 空单元格保留该字段原值，不将原有品名、规格或备注清空。需要清空可选资料时，在面料编辑页明确操作；新建面料时可选规格为空仍允许保存，品号和品名必填规则不变。预览按最终生效值展示更新差异。

**文件内重复与错误行【S-01 已批准】**：按已批准的品号规范化规则检查同一文件内重复品号，列出全部相关行号；该重复组的所有行暂不导入，不自动采用第一行 / 最后一行，也不因导入人选择更新而忽略文件内重复。用户修正文件后可重新预览。

新增行缺少必填品号 / 品名，或填写了不合法数值 / 单位时，明确标明行号和原因，该行不写入，不以占位品号或猜测单位代替。更新行的空单元格先按已批准规则保留原值，再校验最终生效资料；不能因空品名单元格而拒绝已经批准的保留原值行为。

重复组和错误行不阻止其他合法行导入，合法行须经过预览确认后提交。文件内重复行记录为跳过并说明原因，错误行记录为失败并说明原因；未写入的行不产生新记录或部分字段修改。

导入完成后分别展示新增、更新、跳过及失败结果。更新沿用同一面料记录及品号，不新建重复记录，不绕过已批准的身份锁定、规格校验和引用规则；已有画册 / 单据影响清单仍在二期处理。提交时后端重新检查冲突和当前角色，预览后出现的新冲突不得被静默覆盖。表头 / 单位识别、模板和预览布局在 UI 设计中细化。

**导入模板与文件格式【D-03 / 2026-10-13 最新确认，覆盖旧双格式决定】**：一期**仅支持 `.xlsx`** 面料工作簿，不支持 `.xls`，旧文件须先在Excel/WPS另存为`.xlsx`；复用项目现有ExcelJS，不增加额外格式解析依赖。标准模板为**品号、品名、成分、克重、克重单位、门幅(cm)、备注**共七列，不增加启用状态导入列。默认“面料资料”工作表、第1行表头；用户可人工指定工作表与表头位置。品号按文本识别并保持前导零（不能静默把字符串“0012”改成“12”）；原Excel数值单元格没有可恢复的前导零时不可凭空推断。需用真实/脱敏`.xlsx`样本、公式/混合单元格和错误文件验证；解析测试通过不代表提交写库已验。

**表头映射【D-03已批准】**：优先按上述标准七列表头识别，同时支持常用别名（如品号/面料品号、品名/面料品名、成分/成份、克重/克重数值、门幅/门幅(cm)）；允许人工选择工作表、表头行与来源列。品号和品名必须映射不同来源列，可选列可以缺省；未知、重名或多个候选表头须人工确认，不靠列位置、近似字符串或“货号”等歧义名称静默猜测。改变映射、工作表、表头行或单位后必须重新生成并确认预览，不能提交旧预览。

**单位识别【D-03已批准】**：明确列、表头或单元格后缀的 `gsm`、`g/m²`、`克/平方米`统一识别为**gsm**；`mm`、`姆米`统一识别为**mm（姆米）**，两者不做单位换算。纯数值克重没有明确单位时，用户须在导入预览中显式指定本文件无单位值的单位，否则相关行标记失败；多个明确单位来源冲突或未知单位时标记失败，不允许用人工默认值覆盖冲突。新增克重为空不补零；更新空值保留原值，非空新克重缺单位不暗中沿用旧单位。门幅标准统一为**cm**，非cm来源必须先提示用户核实/整理后再导入，不静默比例换算。

采用一张紧凑导入页，文件与收起的字段确认区在上方，八列预览按Excel实际行号显示最终生效值、处理方式与原因；已有品号由导入人二次确认后逐行选择跳过或更新，差异按需在当前行下方展开。预览可按新增/更新/跳过/失败查看，底部明确合法行数；重复项的二次提交确认列出处理数量与原值/生效值变化，同页展示实际结果。取消、更换文件不写入业务资料，后端在提交时重查权限、品号冲突与预览差异，变化需重新确认。此提案仅细化UI，不增加历史产品正确性校验、已有订单/画册影响清单、导入批次追踪或新的角色。

一期：面料属性保存后，关联产品展示最新面料资料，不要求保存前列出受影响产品。二期：再考虑面料修改的影响清单，以及已有画册、订单的资料更新 / 快照处理。本轮不细化、实现或验收这些影响处理功能，也不自动改写已有画册与订单。

### 6.3 产品库

**业务要求【基线】**：通过已有花型配色版本与面料组合创建产品，管理三类图片，展示关联资料。

新增流程：

1. 搜索并选择完整花型编号，例如 1234-1；展示对应版本原图、母版编号、配色信息、花型题材及花型颜色标签。
2. 搜索并选择面料，展示品号、品名、成分、克重和门幅。
3. 检查所选版本配色信息；产品页面没有独立配色序号或身份颜色输入框。需新增或改配色时进入花型库。
4. 按“花型编号 + 面料品号”预览自动产品编号，例如 1234-1-S23；发现已有组合时提示已有产品。
5. 上传产品图片，填写备注和状态。
6. 明确保存，成功后进入产品详情或列表；失败时保留输入并提示原因。

产品编辑界面中的面料属性与花型配色资料均为只读，提供进入相应库维护的入口；产品可选择或更换具体花型配色版本，不直接改写母版编号或配色信息。

**产品列表【用户于2026-10-11明确修订；排版效果待评审】**：**2026-10-16用户修订：暂去掉题材、颜色标签列及对应筛选**。列顺序为花型图、货号、品名、成分、克重、门幅 / cm、图片数量、备注、启用状态、操作，共10列。用户于2026-10-12明确在Stitch独立添加“备注”列：位于图片数量之后、启用状态之前，读取产品自身remark，空值显示“—”；长备注紧凑展示并能查看全文，不读取面料或配色版本备注。此修改纳入正式需求，不得因旧11列文档而删除。花型图为所选配色版本的缩略图，单击直接预览同版本原图，仅保留图片与关闭，不打开产品图库或详情；缺图占位不可点击。移除面料主图及花型 / 配色列。货号是自动产品编号的界面名称，生成与唯一性规则保持；品名读取关联面料品名，不在该列展示品号，面料品号仍用于产品编号和关联。底层关联标签数据保留，本列表暂不展示。操作列提供“产品图”与编辑入口，产品图窗口按三类Tab展示并直接读取原图，不额外增加独立预览页面（2026-10-16追加确认：当前类按需加载，切回复用，关闭清理本次缓存）。货号、品名使用两个独立输入框，分别匹配自动产品货号与关联面料品名。可只填写一项；同时填写时使用AND，结果必须同时符合两项，空框不限制该字段，两框均空时沿用默认启用及其他筛选条件。支持关键词匹配，忽略首尾空格及货号字母大小写；更改一项不清空另一项，清空一项后另一项继续生效。两项与启用状态共同过滤全库后分页，改条件回到第一页，不增加混搜或分类切换下拉。

**产品新增 / 编辑【本轮评审】**：**2026-10-16用户追加：共用产品维护页去掉“允许供样”控件，保留启用状态；编辑保存继续保留既有供样状态，新建沿用原默认可供样。本次不删除底层字段，不将供样状态改写为启用状态，QR-09/AC-97扫码规则保持。**共用紧凑完整页面：顶部返回、取消与保存；花型配色和面料可搜索选择器并排，关联资料仅作紧凑只读摘要；货号自动生成只读，备注和启用状态紧凑排列。图片维护采用面料大图、面料细节图、效果图三个标签页，显示各类数量 / 10，只展开当前类的单张上传、选中批删和缩略图操作；切换类别保留各类草稿及顺序，保存一次提交全部类别，取消经未保存确认后放弃全部草稿。产品编辑标签页仍维护三类草稿；列表“产品图”按IMG-10最新要求也使用三类Tab，直接看原图。数字配色标识在花型库维护；更换版本或面料仍属产品身份变化，已开单锁定身份。

## 7. 状态、修改与删除

### 7.1 启用与停用【已批准】

花型库、面料库、产品库只使用内部启用 / 停用状态，不设置业务审核、已审核 / 待完善等状态。

新业务可选产品同时满足产品、母花型、配色版本和面料均启用。停用父记录不逐条修改子产品状态，但相关产品不能用于新业务选择；记录仍可用于历史查阅。三个库默认仅展示启用记录，并支持查询停用记录。

### 7.2 修改与删除【已批准】

| 场景 | 处理规则 |
| --- | --- |
| 母花型或面料未被产品引用 | 母版编号或面料品号可按现有约束修改；删除前检查全部子版本 / 关联并二次确认，不能留下悬空关联 |
| **任一已保存配色版本，无论是否被产品引用** | **配色序号永久只读，不允许改号**；无引用时可按已批准删除规则确认删除，但序号永久不复用；有引用时不可删除、可停用 |
| 母花型、配色版本或面料已被产品引用 | 普通编辑锁定涉及产品编号的母版编号、版本配色序号或面料品号；不可删除，可停用 |
| 产品未被订单引用 | 允许更换具体配色版本或面料，保存前显示产品编号变化并检查组合唯一性；不在产品中编辑版本配色序号 |
| 产品已被订单引用 | 普通编辑锁定身份；额外身份更正机制尚未批准，不作为一期已批准能力 |
| 产品无业务引用（未开单） | 管理员和业务员均可在列表删除；确认框显示货号，确认后仅删除该产品记录及其图片关联，保留花型、面料和其他记录使用的共享资源；执行时重新检查权限及引用 |
| 产品有业务引用（已开单） | 任一已保存的样布码单、定金单或销售发货码单引用该产品即不允许删除；列表删除禁用并提示“已开单，可停用”，执行端也必须拦截。未保存的界面草稿不构成业务引用 |

面料品名、成分、克重、门幅和普通备注可继续编辑。一期不列出影响清单，不联动改写已有画册或订单；这些资料更新 / 快照策略留待二期。

### 7.3 必填与基本输入限制

- 面料品号与品名必填；成分、克重、门幅可空，不产生资料审核任务。填写克重/门幅时为正数，克重有数值时须有单位，不以零代替空值。
- 花型母版编号、配色版本所属母版和有效正整数配色序号必填。无需身份颜色、配色名称或颜色到代码的映射；不能因无法确定颜色阻止建立版本。
- 产品必须选择具体花型版本和面料；产品不另填配色序号。花型/产品完整编号由系统生成并检查唯一性。
- 图片、花型颜色标签、版本备注可暂缺。颜色标签为花型级可选多选、自定义；不改变数字身份、不从面料或产品实拍推断身份。**4.2.3 已批准系统自动递增分配、不重排、不复用与保存后全部锁号**；不增加4个上限。

## 8. 检索与快速找款

### 8.1 预期规模【本轮确认】

花型库和产品库均按约 2,000 条记录的预期规模考虑查找效率。一期设计与验收必须覆盖这一数量级，不仅验证少量演示记录。花型有母版和配色版本两层，技术设计与模拟数据应明确两层数量和分布，不能仅按母版数量忽略版本及产品关联的查询成本。面料数量另行确认。

### 8.2 查找与筛选

以下为已批准的一期查询范围，具体筛选控件与布局随 R-04 UI 评审确定：

| 库 | 首版查询条件 | 结果操作 |
| --- | --- | --- |
| 花型库 | 花型编号、完整花型编号、花型题材标签、花型颜色标签、启用状态；不设独立配色序号筛选 | 看匹配版本原图、看该版本关联产品 |
| 面料库 | 品号、品名、成分关键词、启用状态；不提供克重单位 / 数值区间或门幅区间筛选 | 看完整规格、看关联产品 |
| 产品库 | 货号、品名两个独立关键词输入框，单项可查，双项AND组合，空框不限；启用状态；暂不提供题材或颜色标签筛选，无克重单位 / 克重 / 门幅筛选 | 看所选配色花型图；“产品图”用三类Tab看原图；不提供配色名称或标签筛选 |

- 花型库的题材和颜色标签是两个独立筛选组，各组仅使用所属维度的标签。
- 同一维度的多个选中值使用 OR，不同维度使用 AND。例如“花卉或植物”并且“蓝色或绿色”；编号、状态与维度条件共同生效，R-21 已批准。
- 花型库颜色标签筛选只看花型级颜色关联，返回匹配花型及其配色，不读取旧版本颜色或产品实拍推断标签。
- 支持自定义标签与初始标签共同筛选；未填写标签的花型可按编号查询，不自动根据关联产品补标签。
- 筛选在全部数据范围内执行后分页，不只过滤当前已加载记录。
- 空结果显示无匹配，并可清空条件；加载或请求失败明确显示状态。
- 以图搜图放二期，一期不实现相似度计算或相似图结果。
- 用户于2026-10-11明确面料库与产品库均取消克重单位、克重数值区间和门幅区间筛选。克重、单位和门幅仍为资料字段，正常展示和维护。面料库保留成分关键词查询；产品列表文本搜索按现行要求使用独立货号与品名框、支持双条件AND组合，其余已确认筛选条件保留。
- gsm 与 mm 资料不直接比较或自动换算；空规格记录正常可查，不增加待完善或审核筛选。两库不提供克重单位 / 数值区间及门幅区间筛选。
- 花型库颜色标签筛选保留；产品库标签列及筛选按2026-10-16用户要求暂去掉。颜色视觉相似搜索不纳入一期。
- 预期规模已明确为花型库和产品库各约 2,000 条，常用查询 95% 在 1 秒内完成的目标已批准；测试环境与记录分布在技术设计 / 验收时明确。

### 8.3 三库资料导出【2026-10-17补齐】

**核心业务规则：一张实体色卡由单一花型母版＋面料品号唯一确定，可动态包含本母版多个配色；同一面料与每个数字配色对应一个独立产品。客户选整张色卡，意味着其全部配色产品都要送样；业务员扫描色卡上的一个二维码，要一次加入该卡的全部产品，不能只记录一个配色。**

1. **独立色卡对象（v1.49补充已批准）**：每张有效卡绑定稳定`card_id`、唯一花型母版`pattern_master_id`与唯一面料`fabric_id`；**当前有效卡的母版＋面料组合唯一**。色卡编号自动组合，无手填SC卡号。仅在旧卡仍有效时同组合重复新建复用原卡/码；旧卡删除后相同组合重建须新ID/新码，旧码永久作废。不得把建卡时`product_id`列表当永久快照，不允许多母版色卡，详情见QR-07～QR-11。
2. **动态集合（2026-10-12确认，2026-10-17收紧建卡前提）**：色卡码长期指向`card_id`，不绑定印刷版本或固定产品列表；**每次扫码读取本卡单一母版与唯一面料共同匹配的所有适用配色产品**。若为同一花型新增配色，并在产品库新增该配色＋同一面料的产品，下次扫原码自动包含新款。若为同一花型新增**另一种面料**产品，不混入旧色卡，必须按新面料建立色卡后再选样。
3. **连续扫码及最新资料（v1.50）**：选择客户及选样会话后，每次扫码查询当时可供样产品并在同一事务追加未选产品，保留扫码时间、操作账号、产品ID集合和来源；不保存属性历史快照。每次查看/刷新按最新主数据读取品名、成分、克重、门幅等。后台新增配色不自动增加已选产品，仍需重扫或主动补选。
4. **重扫增量补选**：同一会话再次扫同一色卡时，必须重新解析当前集合，原有`session_id + product_id`不重复，资料实时读取最新主数据，新产品**只增差集**；无差异提示「已选，无新增」，多一配色则提示「新增1款」。保留每次扫码事件及不同色卡来源；可复核、备注、撤销并留操作审计。
5. **一致性校验（v1.49已批准）**：无效/已撤销码、卡或父身份不存在及范围不一致时明确拒绝且不得泄露资料；当前停用或不供样配色产品**有意排除**，不可错误地判定为漏配；其他匹配产品须完整选入，新增同事务成功或回滚。零可选产品时提示且不产生空选样；已选产品关联保留，资料按最新主数据读取。详见QR-07～QR-11。
6. 清单同时展示**唯一色卡张数**与**已选独立产品款数**；允许比较色卡当前产品集合与客户**已选产品ID集合**的差异，提示新增未选配色。生成客户确认清单；新配色不因后台建产品而自动增加旧客户选样/寄样，**选中不等于已寄样**。

##### 二维码图与Excel编码文本一致【2026-10-14用户明确】

每张色卡创建后持有一个稳定的原始编码文本`qr_payload`（数据设计名），页面二维码以该文本绘图，Excel 二维码列直接导出同一文本，其他App同样以该文本绘图。**一致性以扫码解码文本逐字一致为准**，不要求不同App的尺寸、纠错等级或二维码像素图案完全相同。重复创建、再次导出和新增配色均不重新分配或改变该卡payload；色卡编号仍独立为色卡编号1234-F018，不默认等于编码文本。若既有编码是带令牌的完整链接，导出完整原文；B2-3独立实现采用随机32字节的43字符base64url原文，稳定持久保存并以SHA256摘要查卡；没有生产域名依赖。正式App及真实MySQL尚未接入，不把示例域名当生产地址。导出文本不授予扫码权限，客户/访客仍由服务端拒绝。

##### 9.1.8.1 色卡库新增：输入匹配与只读校对【2026-10-13用户明确调整】

“实体色卡”是二期独立的**色卡库管理页面/对象**：保存已有花型母版＋已有面料的唯一组合、色卡编号和稳定二维码引用，不复制另建花型库、面料库或产品库。现有精简列表即该页设计，正式API、组合唯一约束及业务Excel仍待实现。

1. **输入＋模糊匹配**：新增只有母版和面料两个可输入的单选检索框。花型可按母版编号片段或完整花型编号（如1234-1）查找其母版；完整编号仅用于定位/校对，不增加配色选择、不改变母版＋面料唯一范围。面料按品号或品名片段匹配，编号大小写不敏感；只选已有可选记录，不从自由文字创建主数据。
2. **候选精简与花型校对**：花型下拉候选每项只显示匹配到的母版编号（如1234），不显示图片、已有配色、配色数量或说明；完整花型编号1234-1仍定位其母版1234。明确选中后，校对区自动显示该母版各配色已有图及完整花型编号。母版不设共用原图，每版显示自己的图；缺图/加载失败明确占位，不借图/编造，不增加第三选择条件。
3. **面料候选精简与成分校对**：面料仍支持输入品号或品名片段匹配，但下拉每项只显示面料品号（如F018），不展示品名、成分、克重或门幅；选中后输入框只显示品号，同一窗口校对区只读带出该面料的品号、品名、成分及原克重/门幅。空值显示未填写/—，不能在建卡窗口手填或修改主数据；保存仍引用该面料ID。检索采用普通关键字/编号片段匹配，用户无需编写正则表达式。
4. **输入与身份一致**：必须明确选择已有记录，未选/无匹配不能生成。重新编辑输入立即清除对应已选ID、校对资料与编号预览；晚到查询不覆盖新关键字。鼠标/键盘可选、无结果提示、候选较多可继续查询，不永久限首屏少量记录。取消关闭不写入，再次打开清空未保存草稿。
5. 两项有效记录选齐，自动只读生成色卡编号1234-F018和稳定二维码；**重复组合只复用当前有效卡**，旧卡已经删除则新ID/新码。六列Excel及禁止标签预览/下载/导入不变；校对图不是色卡标签预览。服务端最终校验权限、身份与仅有效卡的组合唯一。**2026-10-16确认：点击“生成色卡”成功后，列表正常提示“已生成色卡”并自动关闭当前新增弹窗；失败保留弹窗及已选资料以便重试。**

##### 9.1.8.2 已建色卡身份、动态供样、删除重建与重新打印【v1.49，2026-10-14业务负责人已批准】

本节为本日最新的**强制业务基线**。如与上文9.1.5的“停用/无法供样待审”、9.1.8第5项、AC-80等旧待审语句冲突，以本节为准。**业务批准不等于已实现；正式接口、DDL、React及真MySQL仍需按下述验收重做。**

**QR-07｜已建色卡身份不可编辑。** 色卡创建后固定`card_id + pattern_master_id + fabric_id`，列表/编辑页**不提供更换花型母版或面料品号**的操作。要换母版、面料，必须删除旧色卡并新建，不得把旧卡的二维码指向其他母版/面料。已有色卡引用期间，对母版编号、面料品号的普通改号及父记录硬删除继续按R-07禁止（409）。同一面料的品名、成分、克重数值与单位、门幅等**非身份资料允许修正**；实际已经变成另一种面料/花型时，不通过改描述偷换实物身份，必须新建主数据及对应色卡。

**QR-08｜删除与重建的新旧码隔离。** 用户在色卡管理页操作“删除”时，旧卡退出可管理/可扫码的**当前有效色卡集合**，其二维码令牌立即撤销且**永久不得重新激活、复用或重新指向新卡**；随后即使同一母版＋面料组合重建，也创建**新`card_id`与全新随机`qr_payload`**，绝不复用历史卡或旧码。重复**创建当前尚有效的同组合**仍返回原卡、原码（QR-03保持）。服务端应保留被删除色卡的不可变历史记录及令牌摘要/撤销事实；历史客户选样、寄样、扫描事件的外键、旧卡身份及操作者来源记录**不得因删除而丢失或改指新卡**。旧码扫码明确提示已作废，不泄露内部资料、不添加选样；不能直接硬删已经被引用的历史记录。删除及令牌撤销必须同一事务成功或回滚，当前组合唯一约束必须调整为**仅约束有效卡**，历史旧卡/旧QR仍全局不可复用。没有创建新的产品单码、打印标签下载/导入功能。

**QR-09｜扫码只纳入当前可供样的配色产品。** 每次扫码在当前有效母版、面料与色卡下，动态筛选同一`pattern_master_id AND fabric_id`的**当前启用且可供样**产品及其启用配色版本；已停用的产品、配色版本或被标记“暂不供样”的产品**不显示、不加入、不在本次解析产品集合里**。部分停用不阻止剩余可选款整卡加入；后续恢复供样，下次扫描可重新包含。后续新增配色且建立同面料有效产品时按QR-03/QR-04增量补选、去重；已选产品关联、实际寄样及扫码记录**不因下架/恢复而被静默删除**，选样资料展示仍读取最新主数据。如整张卡无可选产品，显示“当前没有可选产品”，不得生成空选样明细、空选样来源或虚假新增计数；具体是否保存一次仅用于诊断的失败扫码事件由实现阶段界定，但不能产生任何选样成功记录。**卡或其父母版、面料停用仍拒绝新的扫码选样**；“不再供样”标记与现有`is_active`分开管理的具体存储字段、默认值及权限需在技术方案中明确，不能假称既有产品表已有独立供样字段。

**QR-10｜面料资料更新触发运营重新打印。** 已建有效色卡关联的**同一实物面料**若品名、成分、克重（含单位）、门幅等印刷字段经保存发生**实际值变化**，系统自动把**所有当前有效、关联这款面料的色卡**标记为**“需重新打印”**；字段未变的重复保存不新建提醒。一次面料变动可能影响多个母版的色卡，必须一并标记。色卡二维码及卡ID不变、列表及新导出的六列XLSX立即显示最新资料；**选样资料同步读取最新主数据，不保留资料快照**。产品新增/停用、配色增加本身不触发打印标记。花型图/产品图片如未涉及本实体色卡上实际印刷的内容，不因后台图片维护强制全部重印；如印刷内容范围扩大，应同步补充触发范围，不得让实体卡印刷内容与展示资料悄悄不一致。

**QR-11｜运营完成后手动清除提醒。** 色卡库列表提供**“需重新打印”状态/筛选**及逐卡操作“标记已重新打印”（文案可为“已处理”）；操作者为已有具备色卡管理权限的管理员或业务员，**不新建第三种运营角色或独立审核流程**。状态只有`无需重新打印 / 需重新打印`两种，不强制额外复核人。若先标记待印，随后面料再次更改，提醒持续存在；**并发情况下，旧打印确认不得清除更新后新产生的提醒**（必须以当前变更版本/等效乐观锁比较，原子校验通过才可清除，否则提示资料已变化、请按最新版重印）。删除/失效色卡不再产生新的重印待办；重新创建的是新色卡新码，不继承已删除卡的“已处理”标记。二维码仍只授予经服务端鉴权的业务员选样，色卡管理和导出依照已批准的管理员/业务员角色保持。

**最小验收场景：** 单卡修改品名后标记待印、重导XLSX与页面同值/QR不变；同面料两卡联动标记；无变化保存不标记；连续两次更改、旧版本确认失败；手动确认后恢复正常、再改又标记；产品停用/恢复/新增与配色停用后只见有效集合；零可选时无新增选样；旧卡有选样引用时“删除”使旧码作废、历史可查，同组合新卡产生新ID/新码，旧码永久拒绝；重复创建当前有效卡不换码；不授权用户不可删卡、改打印状态或扫码。

**库内产品资料只读【S-02 已批准】**：在三种单据中选择库内产品后，带出的数字配色标识（沿用单据色号字段）、成分、克重、门幅与货号、品名均为只读，对管理员和业务员一致。米数、单价、各匹米数、扣损等适用于该单据的业务字段继续按单据权限编辑。后端同时限制改写库内产品带出的资料，不能仅靠前端只读控件；不将单据编辑结果回写花型、面料或产品库。该只读规则不触发对已有单据的主数据刷新 / 同步，已有资料值仍按既定保存与输出口径保留。

管理员同样默认使用产品选择，可以主动切换为手工录入，填写临时产品的货号、品名、颜色、成分、克重、门幅等资料。此能力固定归管理员角色，不新增业务员授权开关。手工明细不自动创建产品库记录，也不伪装成已关联的库内产品；若要建立主数据，应通过产品库正常维护。

前端按角色限制输入，后端同时校验，业务员不能通过直接提交手工货号 / 品名或篡改带出值绕过限制。权限依据当前操作人的角色判断，不能因为单据由管理员创建而允许业务员手工改写。

一期沿用现有单据字段保存与输出方式，核对三种单据的编辑、预览、打印 / 导出读取同一业务资料；管理员手工明细也应按实际录入内容正确保存和输出。

**旧单据编辑【S-02 已批准】**：重构前已保存的旧单据中，未关联产品库的原有手工明细允许保留，不强制补建产品或补关联。业务员可直接编辑本人旧单据中的米数、单价等业务字段，不再依赖旧授权开关；原货号、品名只读，不能以旧明细名义改写产品身份。

业务员新增明细、更换明细产品时，必须选择库内符合启用条件的产品；复制旧单据形成新单据时也须选择库内产品，原手工明细不能直接获得新单据的手工录入豁免。此规则不新增“复制单据”功能范围，只约束形成新单据时的产品选择。管理员继续保留已经批准的手工录入能力。

后端依据原已保存单据及明细识别旧记录，校验原货号、品名未被改写，并遵守本人单据范围和动作权限；不能信任客户端声明“旧明细”，也不能借此新增无关联手工明细。旧明细保存、预览及输出保留原有产品资料值。

历史单据产品明细不因主数据更新而自动改写；按权限主动编辑业务字段不属于批量改写或主数据同步。面料主数据修改对已有单据的刷新 / 同步 / 新快照治理，以及对已有画册的影响仍在二期处理，不成为一期关联功能的前置条件。库内产品资料只读与管理员手工模式规则已批准，按本节执行；不因此给三种打印模板增加新的展示字段。

#### 9.3.1 共用产品选择 UI【2026-10-12 待评审提案】
