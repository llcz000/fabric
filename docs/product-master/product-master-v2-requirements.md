## 使用和维护边界

- **新增或修改业务规则**：只修改[项目需求总览](../project/项目需求总览.md)里唯一稳定 ID 的对应条目，不能在 AC、UI手册、技术设计或复盘另立业务基线。这里只写可验收场景，涉及跨域时关联唯一需求 ID。
- **变更影响**：运行 npm run knowledge:impact -- CUSTOMER-07 或 npm run knowledge:changed 定位影响域和源代码/测试候选，再核实真实调用链。
- **旧用例**：源于已取消方案的旧 AC 只能作为负例约束；发现与当前业务冲突时直接修订或删除，旧编号本身不代表新需求。
- **逐条追踪**：每项 AC 的第二列 `对应需求ID` 必须直接列出一个或多个[需求总览](../project/项目需求总览.md)的有效稳定 ID，多个用英文逗号分隔，不得用旧版本号、阶段任务号或文字推断代替。`npm run knowledge:check` 自动阻止孤立 AC、错拼ID和重复关联；`npm run knowledge:impact -- AC-01` 从用例反查业务要求。任何有效需求 ID 必须有直接 AC；知识图谱对缺失关系报错。库存待排期的 AC 只定义未来检查，不能视为已实现、已执行测试或验收通过。
