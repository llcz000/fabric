# B2-5｜实体色卡 v1.49 业务规则确认与开发边界

> 文档定位：项目需求｜主要读者：业务负责人、开发/验收。用途：批准决定的依据；不另作现行规格。

> 2026-10-14 用户明确：停用/不供样产品扫码不列出；已建色卡不可更换花型母版和面料品号，必须删除新建；同一实物面料信息修正后提示运营重新打印，手动完成后清除。随后用户明确**以上内容都同意**，包括旧二维码永久失效、同组合重建也要生成全新二维码、历史选样仍需保留。当前唯一需求基线：[v1.49](product-master-v2-requirements.md)中的QR-07～QR-11/AC-95～AC-99；[B2-5实施计划](../project/项目设计.md)。

## 五项确认决定

| 业务规则 | 已批准行为 |
| --- | --- |
| 动态可供样 | 仅选当前启用且可供样的配色产品；恢复和新增后下次扫码增量；零可选不产生成功选样/空明细，历史资料不变 |
| 已建卡身份固定 | 卡绑定的母版ID和面料ID/品号不可改；更换母版或面料必须删除旧卡并建立新卡，不把旧二维码转指别的商品 |
| 旧码永久作废 | 删除撤销旧码、旧卡ID及历史事件记录留存，同组合重建新ID/码；**只有当前仍有效**的组合重复创建才复用现码 |
| 面料资料更新触发重印 | 同一实物面料的品名、成分、克重数值/单位、门幅发生实际变化时，所有有效引用色卡自动标“需重新打印”；列表与新Excel读最新资料，码不变；新配色或停用产品不触发重印 |
| 运营完成确认 | 当前admin/sales色卡管理权限可逐卡标“已重新打印”、筛选待处理；旧版本确认不得清除之后再次变更产生的提醒，无需第三种运营角色或审核流 |

## 当前实现和差距（只读核验）

- `server/customer-samples/schema.ts` 现仍在 `sample_cards`对母版+面料、card_no做**全局唯一约束**，无退役/待印修订字段，不能安全支持“删旧同组合重建”。
- `server/customer-samples/scanRepository.ts` 现仍对任一不可用产品拒绝整卡（409），而非只列可供样产品；没有完整的不供样独立字段。
- `server/customer-samples/cardLibraryRoutes.ts` 尚无色卡删除与确认已重新打印端点，`fabrics.ts`与xlsx覆盖提交仍需同事务标记相关卡重印。
- B2-3/B2-4现有定向/Edge本机测试不是本轮新增规则的实现证据。正式App/真实MySQL/COS尚未完成本轮联调，未写远程库、未部署。

## 持续有效的边界

实体色卡二维码仅授权且登录的业务员在本人有权限的客户选样会话中操作；客户/访客扫码无权。管理员与业务员均可查看/管理/导出色卡；“运营”是现有人员的岗位，不增加角色/审核流程。历史选样/寄样与二维码来源关系不可因停用、删除或面料改动丢失。仅.xlsx面料导入不恢复xls、单产品二维码/标签预览下载/色卡导入不恢复。
