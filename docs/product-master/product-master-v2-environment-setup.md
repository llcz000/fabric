## 2. V2 的实际技术准备

1. 在远程当前 **MySQL 8.0.46** 版本上建立**隔离测试数据库**并验证幂等初始化，不在运行中的 `fabric_db` 直接测试DDL或清理；隔离库可由研发使用既有SSH/数据库管理能力，在明确授权后建立。
2. 在V2结构中使用不冲突的原生表（建议 `v2_fabrics`、`v2_products`，以及花型母版、配色、标签、图片关联表）。远程已有一个名字叫 `fabrics` 的空表，但其实际字段是订单/金额相关，**不是V2面料表**；不能就地覆盖。
3. 原产品库数据已获准废弃：现有 `products` 1,211 行，5个子表含FK；图片关联1,008行涉及944个不同全局资产。**先验收V2、设计受控清退与图片ref_count生命周期，切换后再清理**，不直接DROP/CASCADE。
4. 118份历史单据、148条明细、库存/客户/公司数据和全局 `image_assets` 必须保留。旧单据产品字段是历史文本，不能强行重新映射旧产品。
5. 开发和部署仍走P0～P7验收Gate：数据库/身份权限/图片/三类单据/性能；真实迁移/旧数据删除/远程发布不能因为本轮只读核验自动执行。

**当前无需你手动完成额外软件安装或连接配置。** WebCodex已能通过项目现有SSH登录并检查远程MySQL；下一项技术工作是隔离数据库准备与V2原生Schema/TDD，实施前核对生产影响与授权。

## 3. 旧指南的错误前提

此前在 Windows 的 `127.0.0.1:3306` 得到 `ECONNREFUSED`，只说明**本机没有MySQL服务**，不能证明远程MySQL故障；此前建议Windows本地安装MySQL Server 8.4已撤销。Windows本地 `.env` 仅属于本地运行上下文，不可用它推断线上数据库地址。
