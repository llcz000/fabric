# 可选 Stitch 改稿与交付流程

默认复用正式React组件；普通字段、筛选和弹窗改动按[UI规范](../ui-design/README.md)交付，不强制Stitch、A/B或额外设计平台。本页只在用户指定或任务实际使用Stitch时适用；工具连接、安装方法以当前工具配置为准，不保留旧研究流水。

## 7. 每轮及时清理 UI 中间稿（2026-10-10 用户确认）

先验证新稿与登记，再按本次明确授权范围清理被替代稿；保留用户独立修改、唯一批准稿和必要原件，不因返回新屏幕ID就认定旧稿已被替换。清理远程设计资产不属于普通本地目录整理授权。

## 8. Stitch 画布与本地原型交付流程（2026-10-11 生效）

### 8.1 先确定交付范围与页面身份

开工列出预期页面、实际项目及屏幕ID；不能只登记工具已经生成的页面。修改前读取目标最新HTML/截图和真实画布，与上次同步稿及本次要求三方对照，保护用户改动。路径/截图哈希不能代替内容核验。

### 8.1.1 修改前读取最新Stitch并合并用户调整（2026-10-12生效）

提示词只写本次变更与必须保留项；列数、顺序、备注和图片归属取最新需求及用户实际改稿，不套旧模板。未知来源差异先保持待核；同范围已明确授权的修订继续推进。操作后若用户又修改，重新读取并合并，禁止覆盖其新增内容。

### 8.2 生成或更新后核验画布

逐页确认真实画布可见、屏幕身份、HTML/截图和本轮要求一致。DomOperationEvent或成功文字不等于稿件保存完整；工具不可用明确未验证。用最新真实快照运行 `scripts/check-stitch-review-delivery.mjs`，该脚本不替代实时工具或视觉审查。

### 8.3 本地原型与画布保持同一轮登记

本地交互预览、远程画布、用户UI接受、正式组件接线、数据库/权限及发布是不同状态。未远程同步不能称远程已交付；本机演示链接不能发客户当正式业务链接。

### 8.4 每轮结束的交付门槛

逐页核对预期清单和实际稿，记录当前ID及必要原件。提炼有效规则到原有规范，证据留现有制品位置；不新建每轮日期报告，不复制第二套当前稿。旧工具调研/安装/价格/试验输出在[恢复包](../maintenance/文档整合与恢复.md)，不作为今天的操作步骤。

### 8.5 最终交付说明

只给一份实际可审查结果：变更、可打开入口、真实验证、未验项和是否已发布。未使用Stitch的任务无需补画布或Stitch专项；生产发布仍由[统一发布工具](../operations/统一发布工具.md)和明确授权控制。
