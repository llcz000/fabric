## 设计命题
用户明确：新页面不仅要功能正确，视觉还应有高端印花面料设计公司的品质感。之前主要复制旧 V2 蓝灰边框与 11/12px 字号，导致新页面风格保守，业务数据表像传统后台。

本次在不改变模拟数据身份、业务行为和测试范围下实现 **两种结构不同的设计方向**，而非在原页面上更换主题颜色。未连接 Stitch、Magic Patterns、Figma 或 v0 云端画布；原型由当前项目代码和已安装的 `ui-ux-pro-max` / `frontend-design` / `fabric-ui-design` 规范辅助完成，不冒称外部设计工具评审结果。

## 同一功能、两种视觉
| 维度 | A · 高端极简 | B · 现代设计工作室 |
| --- | --- | --- |
| 角色 | 内部业务日常查询与比较 | 视觉浏览、花型展示和客户展示前置评审 |
| 核心布局 | 紧凑列表 / 资料表 + 小幅花型预览 | 编辑式顶部专题 + 大图双列画廊 |
| 视觉 | 米白、深灰墨绿、温和留白、弱化线框 | 深海军蓝、暖陶土色、大面积图像 |
| 关键操作 | 每行直接查看花型 / 分享预览 / 二维码 | 每卡直接查看花型 / 分享预览 / 二维码 |
| 密度 | 较高，便于连续扫描多记录 | 较低，便于沉浸式查看多图 |
| 手机版 | 压缩两行操作区，缩略图与信息同屏 | 纵向大图卡片，保留可见操作 |
| 取舍 | 日常效率好，图片沉浸感相对弱 | 视觉辨识度强，长列表浏览成本更高 |

**当前建议：内部色卡管理页以 A 为基础；面向客户的分享展示页借鉴 B。** 这只是方案建议，尚未获用户对正式 UI 的批准，也不代表建议合并两个完整页面壳。

## 交互和业务真实性
- 两版使用 `PILOT_CARDS` 同一组四张模拟色卡、配色与产品；切换版本保留搜索条件。完整花型、面料与效果图片未接入，CSS 色块清楚标为 `DEMO ART`。
- 同步验证 4 色卡、8 产品、9 配色；这些是虚构测试数据，不是业务统计。
- “复制分享”仅复制当前机器预览 URL；浏览器扫码二维码仍为 `DEMO-ONLY-`，禁止当作公开客户链接。
- 表格/画廊和弹窗分别有合理主次、按钮标签、空结果、Esc 关闭与焦点回归；新样板不写入任何服务器。
- 现有工作区未提交改动、正式产品入口、客户权限、历史与单据均保持不变。

## 后续结论依据
1. 由实际使用者审阅 A/B 风格与操作效率，明确选择、差异和不接受项；不得直接推断用户已批准。
2. 选定方向后，将视觉 Token 和交互组件抽到正式 React 共用层，先改一页、验收后再复制，不批量替换所有已上线界面。
3. 只有在原始花型/面料三类图与当前正式业务路由确认后，才考虑将 B 的图库表达接到客户分享。公开分享授权、链接有效期和扫码条件另做安全验收。
4. Magic Patterns / Figma / Stitch 等设计工具仍可按需要单独做同需求对比；本次没有连接/运行这些产品，不能把本次视觉效果归功于它们。
