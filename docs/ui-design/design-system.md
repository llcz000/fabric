# Design System：Fabric UI 视觉规范

> 文档定位：规范与手册｜主要读者：设计/开发/测试/运维及Agent。用途：按当前任务选择对应规范或运行方法。

版本：0.1｜2026-10-14。此阶段整理已有视觉语言，未改样式源码，也未从实时 Stitch 画布重新提取设计系统。

源码路径均相对当前活动应用根目录；定位方法见[项目结构说明](project-structure-audit.md)。

## 依据与适用范围
**优先决策（2026-10-21）**：内部全部业务 UI 按 [内部效率与客户分享边界](product-positioning-2026-10-21.md) 设计。高端美感不等于高装饰密度；内部工作台要快速搜索/编辑/查看，避免大面积 Hero、画廊和没有任务价值的统计。只有色卡分享链接客户可见部分强调媒体展示；下方历史色值是现状盘点，不要求新页面复制旧风格。

优先顺序：用户最新明确决定及当前业务需求 → 已批准页面的相关设计 → 当前 V2 组件 → 通用建议。若新建议与已批准稿不同，提出可审查差异，不把建议当既有批准。

实际源码存在两套视觉值：
- 全局 CSS（`src/index.css`）：品牌蓝 brand-500 #0ea5e9、brand-600 #0284c7；body 背景 #f8fafc、文字 #1e293b。用于既有全局样式。
- V2 产品列表（`src/components/product-master-v2/ProductCatalogV2.tsx`）、面料列表（`src/components/product-master-v2/FabricLibraryV2.tsx`）、色卡列表（`src/components/product-master-v2/SampleCardLibraryV2.tsx`）：蓝紫灰表格与面板，下表为整理出的语义映射。

V2 页面优先延续当前 V2 局部风格；不要只因全局存在另一套品牌蓝就批量替换。第一阶段没有建立共享 CSS token 或通用组件实现；下列语义名用于沟通，尚不是代码变量。

## 字体与信息层级

全局字体栈已为 Plus Jakarta Sans / Noto Sans SC / 系统 sans-serif；编号类等宽字体为 Courier New / Lucida Console。远程字体加载失败时应保持系统字体可读。本次未新增字体依赖。

现有 V2 表格多用 text-xs，标签可为 11px。建议新正文保持 14px 左右、表格保持已批准密度；放大或缩小需实际预览检验。层级顺序为页面标题 → 工具栏/分区标题 → 行内容 → 辅助说明，避免每个字段都做强调色。货号、品号和数字配色保持可分辨、可复制；不得用颜色标签替代配色身份。

## 间距、形状与布局（基础建议）

新设计优先采用 4/8/12/16/24px 间距尺度；小控件与标签用小圆角，已有面板采用 rounded-lg。不要为规范统一批量修改既有间距、圆角或字体。阴影集中用于浮层，数据表以边框与底色组织。

后台以数据表和稳定的筛选区为主：标题/主要操作 → 筛选 → 内容 → 分页。花型、面料、产品和实体色卡分清管理对象，避免为“统一卡片风格”隐藏可比较字段。产品表已有 min-width 1200px 和横向滚动；窄屏应保留列与操作可达性，不压缩到不可读或删除受保护列。

## 图片与状态

图片先保证面料/花型内容准确和可看清。默认预览使用等比适配，允许缩略图与完整预览职责不同，但不能拉伸、改色、重绘原图或以其他产品图填空。无图、加载中、失败分别表达；失败可重试，完整原图应有明确查看入口。不得把图片展示角色混成一个无差别图池。

加载、空库、无筛选结果、网络错误、权限不足、只读、保存中、保存冲突都应有可读反馈。正常有效色卡在选样历史中不额外显示“有效”标识；删除色卡显示“已失效”，保留已选产品。此为当前业务口径，区别于三种单据保存后的属性冻结规则，见当前需求。

## 下一阶段

只在真实页面使用暴露重复样式后提炼共享 token/组件。提炼前提供差异预览与影响范围；本阶段不引入新 UI 框架、不建立第二套主题、不重做整站。
