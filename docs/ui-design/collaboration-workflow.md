# WebCodex + Codex ACP 协作流程

> 文档定位：规范与手册｜主要读者：设计/开发/测试/运维及Agent。用途：按当前任务选择对应规范或运行方法。

版本：0.1｜2026-10-14。用于现有链路的规范传递，不新建编排平台、不更改 provider 或并发配置。第一阶段未启动 ACP 编码代理。

## 统一读取入口

仓库根 AGENTS.md → .agents/skills/fabric-ui-design/SKILL.md → docs/ui-design 中本任务所需文档。产品业务任务继续按 fabric-product-master-v2 技能路由当前需求；两个技能分别负责 UI 约定和业务/实施边界。

Codex 项目技能留在 .agents/skills/；agent/skills/ 中既有设计工具技能继续保留。WebCodex 是否发现某目录由实际配置和技能列表决定，先按精确名称尝试 skill_load；加载失败则直接读取项目 SKILL.md 和相关规范，明确使用文件方式。不要声称注册成功、自动注入或 ACP 实跑通过。若将来需要安装到 Runner Skill store，应独立完成打包/安装校验，本轮不修改该存储。

## 默认执行链

1. 检查现行需求的相关小节、目标组件与未提交差异；单个 Agent 直接执行。已有批准范围继续推进，缺业务选择时只澄清该选择。
2. 明确文件归属与可审查产物。UI 方案默认复用当前 React/model，提供隔离的可交互预览；已批准修订可按授权直接修改。
3. 评审检查业务、视觉、状态；明显新布局的 UI 接受先于正式应用接线。Stitch 无额外价值或同步成本高时省略，不补形式性画布。
4. 应用代码阶段按项目规范完成行为验证；同一轮必要回归由执行者串行统一跑。文档工作只做与文档相关检查。
5. 交接提供路径、可打开结果、实际验证、未完成项；更新相关进度/复盘。连接成功与任务登记均不代表代码已交付。

## 可复制任务简报

> 目标：修订【页面/一个交互】，预览可复现【验收行为】。
> 依据：需求【版本/小节/AC】，规范【相关路径】，已批准/待审边界【依据】。
> 只读入口：【组件/model/API 和必要小节】，避免全文重读历史。
> 写入归属：【精确路径】，共享入口由单一集成负责人修改。
> 设计工具：默认 React 可交互预览；仅需改 Stitch 时加载该工具规范并读取远程最新稿。
> 验证：【专项行为、实际视觉、必要 lint/build】，说明模拟与真实环境。
> 禁止扩展：【数据库/生产数据/部署等未获授权范围】。
> 交付：【预览入口、差异、结果、剩余事项】。

使用 ACP 时，把这些项目路径和现行约束显式放入任务上下文；不要假定 ACP 会继承当前聊天内容或已加载技能。模板不构成自动派发授权。

## 并发和共享文件

默认单 Agent；确需已授权的独立任务拆分时使用既有 [上下文手册](../product-master/product-master-v2-agent-context-handbook.md) 的短简报和文件归属。并发限制以当前 Runner/ACP 实际值为准，不固化历史 max_concurrent_runs=1，也不将 Runner Job 限制等同于 ACP 限制。

已有大量未提交 V2 文件时，不能从旧 HEAD 直接创建缺内容的工作树。使用既有预检核验真实基线，保留用户修改；不得借整理规范执行 add -A、reset、clean、批量 stash。AGENTS.md、知识库首页、统一进度和共享装配文件的编辑应使用最新读取的精确锚点/版本保护，遇到冲突重新读取。

## 最短交接

结果：DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED。
附：需求依据、实际变更路径、可打开产物、已执行验证与结果、问题和下一步。
独立列出 UI 接受 / 应用编码 / 正式接线 / 真实 API或MySQL / 部署状态。未执行就写未执行，不能把截图、静态 PASS 或工具连通当业务验收。
