# UI Review Checklist：可复用验收清单

> 文档定位：规范与手册｜主要读者：设计/开发/测试/运维及Agent。用途：按当前任务选择对应规范或运行方法。

这是 UI Gate 的逐项检查项目，不重复定义门禁执行步骤；业务需求以[唯一需求总览](../project/项目需求总览.md)为准，完整证据提交方法见[UI Gate](ux-delivery-gate.md)。

每项记 PASS / FAIL / 未验证 / N/A（附原因）。PASS 必须有对应截图、实际交互或测试结果；文件齐全、静态脚本通过和用户批准分别记录。发现问题标 P0（越权/数据破坏/核心不可用）、P1（核心流程受阻）、P2（局部问题），附触发条件和修复责任。

## A. 范围和依据

- [ ] 写明稳定需求ID、对应AC、页面身份、设备范围和改动范围；使用 `npm run knowledge:impact -- 需求ID` 核对受影响模块。
- [ ] 区分新页面、已有页修订、独立评审组件和正式应用入口；仅覆盖已授权范围。
- [ ] 对照已有批准稿及用户修改；业务字段未因视觉精简被删除。使用 Stitch 时先比对实时远程稿。
- [ ] 工具记录为 React 预览 / Stitch / 其他。未用 Stitch 时无需生成画布或伪造屏幕 ID。

## A.1 业务必要性与最短路径（每个受影响页面必须核对）

- [ ] 逐个审查原有和新增按钮、字段、状态、标签：写清使用者、触发时机、业务价值和必要性；找不到现行需求/真实场景的入口不得仅因旧代码存在就保留。
- [ ] 同一目的只保留一条清晰操作路径，不并列提供重复扫码、刷新、管理/查看或状态维护；详情页先显示主体数据，手机首屏不得被次要操作挡住。
- [ ] 核对勾选框实际代表“选中卡”还是“选中卡内配色”、默认值是否会误操作；任何可能恢复已取消项、扩展批量范围或产生写入的行为必须由用户显式选择，未选择时禁止提交，关闭/取消不写入。
- [ ] 验证图标与文案只表达一次操作意图；关闭尽量单一入口，图标关闭具辅助名称、Esc与焦点归位，失败时保留选择和重试，不混淆“操作未确认”和“成功”。
- [ ] 实际导航遍历本次改动影响的首页、明细、二级标签、弹层及嵌套子流程，分别留1440px与360px正式 CSS 截图；不能只测“按钮可点击”，要检测整页元素的业务必要性、首屏可读性和重复操作。未覆盖页面不得标通过。

## B. 视觉与可读性

- [ ] 标题、筛选、内容、操作、分页层级稳定；V2 局部风格与既有页面一致。
- [ ] 产品列数及备注位置以最新需求及已批准页面为准，不沿用历史固定12列；长备注可展开，规格单位与 null 表达正确。
- [ ] 原图等比、未改色/拉伸/替换；无图和失败有独立提示，完整图可查看。
- [ ] 实际检查约定桌面宽度及相关窄屏；表格滚动、弹窗、候选列表和操作可达。移动扫码页应按实际目标手机尺寸检查。
- [ ] 焦点可见、文字对比可读；不能仅凭颜色区分状态。记录检查视口和实际截图，未测对比度就写未验证。

## C. 交互与状态

- [ ] 覆盖加载、空库、无匹配、错误、重试、只读、保存中、冲突与取消。
- [ ] 筛选逻辑、分页重置、快速切换的响应次序正确；不局限于当前页过滤。
- [ ] 对话框标题、关闭、焦点恢复、键盘导航、图标按钮名称和字段提示可用。
- [ ] 失败保留草稿，重复提交被阻止；成功后列表/详情更新与服务端结果一致。
- [ ] 多选集合与导出范围一致；有导出功能则验证真实下载和内容，二维码/文本来自同一卡 payload。

## D. 业务与数据边界（按页面选择）

- [ ] 已保存数字配色只读，自动新增单调递增；已删除序号可通过明确文件名导入复用且不得改变原历史身份。
- [ ] 图片归属和三类计数正确；共享资产移除不误删引用。
- [ ] 管理员/业务员按现行简化角色显示操作，不恢复旧独立授权位；服务端拒绝越权有独立证据。
- [ ] 三种单据历史明细保护与管理员手工例外正确；不因新版 UI 改写历史身份。
- [ ] 色卡有效组合、旧码永久作废、重建新身份、引用保护及重印提示符合现行需求，不恢复已取消的供样维护控件。
- [ ] 选样按当前需求读取最新资料，删卡显示已失效而保留已选产品，正常不标有效；不与已保存单据冻结混用。

## E. 交付与批准

- [ ] 可打开的预览/文件、截图、启动入口与修改范围已登记；模拟数据明确标注，不含客户敏感信息。
- [ ] 若操作 Stitch，按既有第8节核对预期页、真实画布、HTML/截图与登记；只读旧资产不能标本轮 canvas_verified。
- [ ] 按改动选择必要验证：文档检查链接/技能元数据；交互改动跑对应行为测试；应用改动按项目规范补 lint/build 与必要回归。
- [ ] 同一轮应用回归统一串行执行，避免重复运行和临时目录冲突。
- [ ] 用户 UI 接受、代码完成、正式接线、真库验证和部署分别标状态；已获批准的范围不反复询问。

## 评审记录模板

仅将项目和检查项用于现有 UI Gate 结构化证据，不另建一份评审记录；证据范围与 SHA 验证以[UI Gate](ux-delivery-gate.md)为准。

| 项目 | 填写 |
|---|---|
| 日期 / 评审人 | 实际日期与身份 |
| 需求 / AC / 页面 | 版本、小节、业务页面名称 |
| 范围 / 文件归属 | 本轮允许修改的路径 |
| 工具 / 预览 / 视口 | 可打开入口、使用工具、实际尺寸 |
| 证据 | 截图、实际交互、命令与结果路径 |
| A～E 结果 | 每项 PASS / FAIL / 未验证 / N/A及原因 |
| 问题 | 严重度、复现方式、影响、责任方 |
| 接受与剩余事项 | 用户确认依据，未测的 API/数据库/集成 |
| 下一步 | 在当前授权内的一个具体行动 |
