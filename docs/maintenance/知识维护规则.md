# 知识维护规则

> 维护准则。需求写业务，设计写实现，状态写已完成/未验，手册写可重复操作；不在本文件积累每轮清理流水。

## 唯一位置与准入

| 信息 | 唯一维护位置 |
|---|---|
| 全项目业务与批准范围 | docs/project/项目需求总览.md |
| 产品主数据详细条款 | docs/product-master/product-master-v2-requirements.md |

docs/00-首页.md 是唯一总入口，分类检索只作导航。需求只写做什么和验收判据，技术方案按需求编号落到设计中；冲突以最新明确批准要求为准。

新增文档必须同时满足：有独立长期读者和问题、现有文档无法合理容纳、有明确权威来源及退出条件。否则更新已有专题。禁止为同一轮工作分别生成计划、交付、复盘和摘要；只有出现可跨任务复用的新根因时才更新已有复盘，确需新主题时用模板并登记索引。用户要求不新建过程文件时优先遵守。

## 保留、合并与退出标准

- **保留**：现行需求/规则、仍有效的独有批准证据、真实运行或测试入口及其必要配置、尚未转移的独有设计和开放Gate。必须能说明谁会因什么问题打开它。
- **合并**：同一规则或技术约束多处重复，只保留一个正文；其他入口改链接。代码可直接查询的列数、默认值、依赖版本、每轮测试数字不在多份规范抄写。
- **归档候选**：重复、被新专题完整替代的过程记录，先转移有效约束/证据环境及未验事项，再退出日常目录。仅加“历史参考”不是完成目录收敛。
- **不适用**：本任务没有可替代历史文件，不为交付格式创建空报告。

日期旧、无引用、单测通过或 Git 干净均不能单独证明可删。引用存在也不是永久保留理由：先判定该引用是否仍必要，再修复调用方或入口。原始批准证据和用户改稿不能擅自改写签收含义。

## 任务完成后的强制归档 Gate

每项任务收尾在现有专题或当前状态记录相关历史资料的保留/归档候选/不适用；不为这个字段新建文档。资格仅两类：

1. `fully_accepted`：本任务约定的全部验收已通过，有实际范围与证据；未测不能算通过。
2. `superseded`：新专题已承接独有批准决定、安全约束、失败原因、证据环境和开放Gate。项目整体尚未验完不妨碍已替代过程原文退出；未验事项仍在唯一状态中可定位。

按顺序执行，缺一步停止：

1. 列精确文件白名单，逐篇语义审查及替代定位；检查代码/脚本/技能/当前需求的依赖，不能批量清目录。
2. 提炼独有约束与开放Gate到现有权威文件，同步修复所有当前入口、脚本和链接；不把旧任务ID、旧漏洞、旧测试数恢复为今天的待办。
3. 在仓库外 `D:/fabric-knowledge-backups` 的同批目录保存相对路径、字节数、SHA256及原件独立副本，重新读取逐文件验哈希；不覆盖旧备份。
4. **机器只读预检**：外部 `review-plan.json` 使用 `fabric-v2-doc-archive-plan-v1`，运行 `node scripts/check-fabric-v2-doc-archive.mjs <review-plan.json>`。FAIL不得移出；PASS也不是删除或部署授权。
5. 仅按已授权、已审查白名单移出；验证导航、技能/相关静态检查、精确源码差异和 `git diff --check`。出现断链或遗漏约束，恢复本批对应原件并修正，不重置其他人的工作。
6. 恢复时先核清单和文件哈希，在独立目录比较后选择性恢复；禁止整包覆盖较新源码/需求/配置。批次审查、哈希及移动回执留在同一仓库外清单；临时执行脚本用完删除。

预检清单逐项包含：`source`、`replacement`、`reason`、`evidence/evidence_phrase`、`unique_information_reviewed:true`、`open_gates_reviewed:true`、`retained_facts:[{file,phrase}]`、`pending_gates:[{file,phrase}]`、`archive_copy` 和64位小写 `sha256`。证据与短语必须真实存在；fully_accepted另需acceptance_confirmed:true且pending_gates为空。布尔值和机器检查不能替代人工语义审查。

## 源码、数据和临时输出

HTML、TS、JSON按实际用途判断：正式入口、测试夹具、构建/测试配置及依赖锁均可能是必需源码；不按扩展名删除。废弃入口退出时连同调用方和源码清单精确调整，保留其它源哈希，不自动接纳未知改动。

运行/客户数据、.env、.local、uploads/template、原始Excel/图片、成片、用户设计稿、当前和回退冻结制品及有独有工作的工作树受保护；不是文档垃圾。临时测试输出由创建方在进程退出后清理；发布证据按恢复依赖保留。普通开发默认单工作区、单Agent；不为整理目录创建新工作区。

同轮目录或行为改变必须连带核对现行规范、技能和检查器。链接可打开不等于内容正确；过时断言须用真实正例与负例修正，不能恢复已取消规则求绿。历史测试、模拟API、真实MySQL、浏览器、微信真机、人工视觉及正式发布分别记证据，未验不签收。文档不存密钥、令牌、连接秘密或客户敏感数据。

恢复总入口为[文档整合与恢复](文档整合与恢复.md)；此处只维护通用规则，不追加日期补丁或每轮通过数量。
