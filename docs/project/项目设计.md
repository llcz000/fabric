# Fabric 技术设计与模块边界

> **现行设计入口**｜核对日期：2026-10-24｜依据：当前 `server.ts`、`src/App.tsx` 与已批准[项目需求总览](项目需求总览.md)。做什么看需求，做到哪看[项目现状](项目现状.md)，业务规则以需求总览为准；可测试场景看[AC验收清单](../product-master/product-master-v2-requirements.md)，本页只说明实现方式。本页只写当前怎么实现、实现约束和未验证边界。

## 1. 唯一正式应用

`D:/fabric` 是唯一正式源码仓库和开发入口；`server.ts` 仅启动 V2 生产运行时 `server/product-master/v2ProductionRuntime.ts`，生产配置不成立时拒绝启动，不回退旧服务或 JSON；`src/App.tsx` 仅按 V2 运行模式呈现 `V2App`，`/s/` 与 `/c/` 公开分享由 `PublicPatternPage` 受限呈现。历史文档中的“旧 App 尚未切换”“V2 未挂载”只代表其旧审查日期，**不再是当前事实**。软件存在不等于本轮已做生产 MySQL/微信真机验收。

技术栈 React/TypeScript/Vite、Express、MySQL、腾讯 COS、Sharp、ExcelJS；具体版本及依赖以仓库 `package.json` 为准。线上发布以统一发布器冻结包和可验证生产回执为准。

## 2. 业务模块与需求关联

| 业务 / 需求 | 代码/设计依据 | 关键边界 |
|---|---|---|
| 登录、会话和管理员权限 / AUTH | `server/access/` | 服务端校验当前身份；单据按原开单人 owner 范围，不因客户列表或 UI 隐藏放宽。保留有效安全保护，不复活旧独立权限分支。 |
| 花型、数字配色、面料、产品 / V2-01～05 | `server/product-master/`、`src/components/product-master-v2/` | 配色号和图片属于具体配色；产品为“配色 × 面料”；删除检查有效引用；题材分类以现行需求词表为准，不增加颜色筛选或无用启停。 |
| 花型/面料导入 / EX-03～06 | 产品主数据导入路由及预览组件 | 花型多文件或目录按文件名识别、单张失败不阻断；面料只接收 xlsx，直接模板说明，不做列映射 UI；品号仅空校验。 |
| 三类单据、输出及统计 / DOC、OUTPUT、QUERY、STATS | `server/order-v2/`、`src/components/document-product-selector/`、`src/lib/documentPrintModel.ts` | 保存时冻结行产品资料；同一金额计算模型服务于读写和输出；销售额与定金合同金额分开；删除须过后端引用/所有权校验。 |
| 实体色卡、选样和客户分享 / V2-08～15 | `server/customer-samples/`、`server/customer-share/`、`src/components/customer-share/` | 色卡身份绑定花型/面料，不做旧码复活；对外稳定链接只公开许可的图文，不暴露客户、价格、内部操作。 |
| 轻量客户档案/回访 / CUSTOMER-01～08 | `server/` 客户 API 和 `src/components/customers/` | 单业务员优先；无寄样跟进模块、无协作归档页面；三类单据列入历史但定金不重复计销售额；仅管理员删除客户且保留历史单据快照。 |
| 图片资产与引用保护 / IMAGE | `server/image-assets/` | 上传解码、身份隔离、引用计数与资产回收；不以删除业务记录为由移除其他记录仍引用的图片。 |
| 后续库存 / STOCK | [需求第2.7节](项目需求总览.md#inventory) | 明确待排期，不把已存在历史算法当作本次已验的新库存功能。 |

细粒度数据结构/API 看[数据与API](数据与API.md)，以当前 server/product-master/、server/order-v2/ 及实际 Schema 为准；旧设计草案不得直接作为数据库迁移或新增需求。

## 3. UI、单据和导出设计不变量

- 全系统是**内部工作台**，只有受控公开分享页供客户打开；内部列表/弹窗追求快速检索、多选、少跳转与操作效率。参见[UI 规范入口](../ui-design/README.md)。
- 新建/编辑交互必须保护未保存草稿。选择器关闭、Esc、请求失败不可误触提交或丢弃原选择；长列表多选及缩略图应做实际数据边界测试。
- 单据预览/打印/PNG/Excel使用相同展示语义；客户、公司、日期、金额和条款以保存/当前配置规则为准。**固定打印宽度和断行**不能依赖桌面浏览器视口；可收缩头部设置 `min-width: 0`、长文本安全换行，避免窄屏/导出时右边界错位。
- 不将详情照片、面料整体、细节、效果图之外的内部图片/源文件/客户字段包含在公开投影中。H5 图片以移动微信场景优先验证。

## 4. 安全、环境与质量门禁

- MySQL 是当前业务的权威存储，真实迁移/回退必须核对目标环境身份、备份与事务；旧本地 JSON、浏览器缓存不得充当线上事实来源。
- 服务端认证、数据归属和参数校验必须覆盖读、写、搜索、统计和分享投影；上传真实检查格式/像素/大小，拦截内网代理与路径越界，不能只判断扩展名。
- 每次相关变动进行范围内测试、TypeScript、构建及 UI 实际交互核验；旧测试通过数字不等于当前浏览器/微信真机、目标 MySQL 或生产环境验收。
- 仓库唯一根 `D:/fabric`，并行开发才临时创建工作树，合并须经过 SHA256/源码、规格、独立审查与串行回归门禁；完成后退役。见[并行开发规范](../development/Fabric并行开发与合并规范.md)。
- 发布只使用[统一发布工具](../operations/统一发布工具.md)；用户授权、冻结制品、备份恢复、远端和公网验证各自独立。未明确授权不运行部署。

## 5. 历史设计与现行决策冲突的处理

以用户最新确认的[需求总览第2.3.1节](项目需求总览.md#catalog)、[客户第2.11节](项目需求总览.md#customers)及当前源码为准：去掉旧启停/供样状态、复杂归档、寄样管理、重复删除审批和旧“canManageOwnOrders”双授权开关的业务设计。历史实现计划和旧知识库不再属于日常设计基线。仍未验的真实账号/数据库/微信实机、COS、并发与备份回滚，应在[当前状态](项目现状.md)明确登记，不按“旧记录被归档”自动标记完成。
