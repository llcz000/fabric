## 2. 技术栈与部署基线

React 19、TypeScript、Vite 6、Tailwind 4；Express 4、Zod、Multer、Sharp、MySQL、腾讯云 COS、ExcelJS、html2canvas-pro。版本以 package 文件为准。

- **MySQL 为业务主路径**，服务端 JSON 与浏览器缓存为兼容降级路径，不能作为事实来源。
- **图片资产**由 `server/image-assets/` 提供隔离上传、派生图、受控访问、引用回收，不新建第二套图片存储。
- **V2 独立模块已实现但未挂正式入口**：`server/product-master/`、`server/order-v2/`、`server/customer-samples/`、`server/customer-share/`、`server/access/`。

## 3. 模块划分与所有权

总控独占：`server.ts`、`src/App.tsx`、`server/product-master/v2CatalogAssembly.ts`、进度文档、schema 与迁移。子任务不得同时修改总控独占文件。

| 模块 | 代码位置 | 职责 |
|---|---|---|
| 身份与权限 | `server/access/` | 登录、会话、角色、数据归属、动作级鉴权 |
| 三库主数据 | `server/product-master/` | 母版、数字配色、面料、产品、标签、导入、schema |
| 单据 | `server/order-v2/` | 三种单据、owner 范围、历史明细保护、计算、产品引用 |
| 色卡与选样 | `server/customer-samples/` | 实体色卡、动态扫码、选样会话、实时资料、软移除、重扫恢复、重印标记 |
| 客户分享 | `server/customer-share/` | 受限公开数据投影、链接令牌；公开 API 与 H5 待开发 |
| 图片资产 | `server/image-assets/` | 上传校验、派生、签名访问、引用回收与对账 |
| 旧入口 | `server.ts` + `server/products/` | 仍承载旧产品路由与旧登录；按切流 Gate 逐步替换 |

**权限要求**（对应 AUTH-04、REL-03、V2-12）：内部业务所有读取与写入入口在服务端逐次校验登录身份、动作权限与数据归属，不依赖界面隐藏，旧接口与新模块遵守同一规则。花型 H5 通过有效分享链接免登录访问；公开接口逐次校验链接有效性，仅返回允许公开的图片与成分规格，不返回价格、源文件、客户及选样资料，不提供内部业务操作。

## 5. 关键设计决策

### 5.1 销售单多匹录入（S1）

**需求依据**：DOC-06 一行标识一个货号，行内按匹录入，不设匹数硬上限。

现状偏差：`src/types.ts:26-38` `SalesItem` 用 `rollNo: string` + `meters: number`，即一行一匹；`server.ts` 存 `piece_meters` JSON 数组，两处模型不一致。

设计要点：

- 行内匹集合为一组米数输入，匹数 = 非空输入的条数，毛米数 = 各匹之和。
- 输入位数量属界面默认值，不是业务上限；不足时可追加，不足不影响已有数据。
- 旧 `piece_meters` 数组作为历史兼容读取，新写入统一到行内匹集合。
- 扣损保持行级，单头汇总扣损合计。

### 5.2 单据汇总字段口径（S2）

**需求依据**：DOC-05～09 与 2.5 节汇总字段矩阵。

现状偏差：`src/types.ts:78-105` `DocumentData` 只有 `totalMeters/totalRolls/totalAmount/receivableAmount/deposit/deductionMeters/settled`，需统一 `deposit` 为定金金额，并补充定金单的定金百分比字段。

设计要点：

- 定金统一使用金额字段；定金单手工填写定金百分比，系统按合计金额×定金百分比÷100 计算定金金额。
- 销售发货单手工填写定金金额。
- 金额计算使用十进制精度：各行金额先四舍五入到两位小数，再汇总；定金单按合计金额×定金百分比÷100 计算定金金额后四舍五入到两位小数，应收金额使用合计金额减定金金额；保存、重读、预览与导出共用同一计算口径（DOC-08）。
- 销售发货单与定金单均按应收金额＝合计金额−定金金额计算，不作独立可编辑字段。
- 样布不设定金与扣损；定金单不设匹数与结清标记。
- 米数、匹数、合计金额与扣损合计由明细派生；定金金额按单据类型取输入值或计算值，应收金额据此计算；自动计算字段不接受手工覆盖（DOC-08）。

### 5.3 大盘移除均价（S4）

**需求依据**：STATS-01 已删除均价。

`src/components/StatsDashboard.tsx:101` 与 `:137` 两处「平均单价」卡片需移除。其余统计口径按 STATS-01、STATS-02 执行，服务端按 owner 范围聚合，前端不做二次过滤。

### 5.4 权限整改（S5、S6）

**需求依据**：AUTH-02、AUTH-05。

当前管理员对他人单据仅放开查看，需放开修改与删除并保留原开单人与操作记录。整改点位于 `server/access/` 策略层与单据写路径，改动须与旧接口切流 Gate 一并验收，避免两套权限并存。

### 5.5 库存扣减（S7，待排期）

**需求依据**：STOCK-02、STOCK-03。

现状 `server.ts:1484-1490` 的台账按明细行计匹数且实时 join 单据表，与「按分匹条数、保存即扣、删改冲销」的新口径不符。设计需先确定扣减流水的持久化方式，再实施。

### 5.6 花型公开链接（S10）

**需求依据**：V2-12、REL-03。

链接稳定绑定母版，每次访问按母版和配色的当前启停状态生成公开内容。停用配色不返回展示；母版停用或没有启用配色时提示“暂不可用”。重新启用后原链接恢复展示，不因停用撤销或换发链接令牌；不提供手动撤回功能。
