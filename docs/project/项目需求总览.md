## 1. 业务场景与流程

### 1.1 准备公司与产品资料

1. 管理员和业务员维护统一开单设置，包括公司、收款码、签字栏文案、备注条款；修改后，新单和全部已开单据的展示、打印及重新导出都使用最新设置。
2. 两种角色均可维护产品资料及图片，团队共用同一份资料。
3. 产品资料只由花型库、面料库和产品库管理；具体配色与面料组成产品，满足启用条件后用于新业务。

### 1.2 给客户开单并交付

1. 管理员或业务员按业务选择样布码单、销售发货码单或定金单，填写客户、日期和明细，并引用统一开单设置。默认选择库内产品，仅管理员可主动使用手工录入模式。
2. 按单据类型自动计算总计米数、总匹数、合计金额与应收金额；销售发货单另算扣损合计并手工填写定金金额，定金单按手工填写的百分比算出定金金额。校验后保存，失败时提示并允许继续编辑，不能显示保存成功。
3. 保存成功后预览，按需输出 PNG、打印 Excel 或 JSON。后续修改更新原单；复制则形成新单，不覆盖原单。保存时冻结的产品资料不随后续修改追写旧单。
4. 销售发货单的应收金额为合计金额减定金金额；定金单不设应收金额，列表与大盘不汇总定金金额。

### 1.3 查找历史业务和经营情况

1. 用户按客户、产品、日期、类型和结清状态查找自己有权查看的单据。
2. 展开命中明细、查看合计，按权限查看、修改、复制或删除单据。
3. 通过大盘查看分类数量、米数、金额、品名排名与最近单据；管理员看全公司，业务员只看自己开的单。查询、输出和统计始终遵守同一数据范围，不能借报表查看他人单据。

### 1.4 管理入库与库存

库存功能不在当前实现范围，以下为已确定的口径，待排期实施。

1. 管理员或业务员按入库日期、品名录入匹数、米数和备注，形成入库记录。
2. 样布及销售单据形成出库，定金单不出库。台账按入库减出库计算结余，支持按品名查询。
3. 出库匹数按销售行内已填分匹的条数计，不按明细行数计。单据保存时扣减库存，删除或改单时按差额冲销。
4. 删除入库记录须确认并重新反映台账结果。

### 1.5 为客户选样，再衔接寄样

1. 系统已登记且有效登录的管理员或业务员进入客户选样单，扫码或搜索有效色卡；补选列表首列色卡编号，一行一卡，展开默认全选可供样配色，也可取消部分勾选。支持整卡加入及加入勾选，取消按货号补选；未建卡产品不可选，跨面料须先建对应色卡，不另设扫码授权开关。
2. 检查当前色卡、产品及关联资料的启用/供样条件与卡内归属；未选则添加，已选则提示重复，已移除项可恢复。停用或暂不供样项不进入勾选；零勾选禁写；无权限或已关闭选样单拒绝添加；整卡/子集写入失败整体回滚，人工选卡保留来源而不伪造扫码。
3. 添加后刷新结果并读取最新产品资料，移除保留历史。确认选样后按实际批次登记寄样，再记录客户反馈和跟进结果。客户公开看图走花型分享链接，不能通过内部色卡码读取选样清单。

### 1.6 团队协作与账号

1. 管理员新增系统账号，业务员不能新增账号；用户使用系统登记的账号登录，账号停用或删除后原会话立即失效。
2. 业务员查看、编辑自己开的单；管理员可查看、修改和删除全部单据，修改或删除他人单据时保留原开单人记录。手工录单只对管理员开放。
3. 两种角色均可导入面料和导出资料，重复记录显示差异，由当前导入人二次确认处理方式后执行。

### 2.5 开单、明细与计算（BASE-02）

| 编号 | 要求 |
|---|---|
| DOC-01 | 三种单据支持创建、查看、编辑、保存、复制和确认删除；复制不覆盖原单，权限按 2.1 节 |
| DOC-02 | 单头含类型、编号、日期、客户、开单人和收货人；公司信息、签字栏文案及备注条款引用统一开单设置，定金单另含收货地址与联系电话 |
| DOC-03 | 默认编号由 YB/XS/DJ 前缀、日期和序号组成，可编辑；客户输入可参考已有客户名称 |
| DOC-04 | 支持增加、删除、清空明细；保存须有客户及至少一条有效明细，空白行不入单 |
| DOC-05 | 样布行金额＝米数×单价；汇总总计米数、总匹数（明细行数）和合计金额，应收金额等于合计金额；不设定金和扣损；支持结清标记 |
| DOC-06 | 销售明细一行标识一个货号，行内按匹录入各匹米数，初始10个输入位、可追加；输入未完成或无效时不能作为清空保存，匹数与匹数上限不设硬限制、可按需增加输入位；匹数取已填分匹的条数，毛米数取各匹米数之和；行扣损米数按行填写，行金额＝max(0，毛米数−扣损)×单价；单头汇总总计米数、总匹数、合计金额与扣损合计，手工填写定金金额，应收金额＝合计金额−定金金额；支持结清标记 |
| DOC-07 | 定金单不设匹数和结清标记；输入定金百分比，系统按定金金额＝合计金额×定金百分比÷100 计算；不设应收金额，不将合同余额当应收；不能把百分比当金额填写 |
| DOC-08 | 金额保留两位小数；每行金额先四舍五入到两位小数，再相加得到合计金额；定金单按合计金额×定金百分比÷100 计算定金金额后四舍五入到两位小数；仅销售发货单的应收金额用合计金额减定金金额，定金单不设应收金额；开单设置取当前值，产品资料取本单保存值，客户/米数/价格取本单业务值；总计米数、总匹数、合计金额与应收金额按单据类型自动计算，不手工覆盖；保存、重读、预览和导出保持对应字段及计算一致 |
| DOC-09 | 定金统一以金额表示，定金百分比仅作为定金单的计算输入；列表与大盘不汇总定金金额 |

2026-10-18单据UI纠偏：V2接线沿用已发布页面的信息层级。编辑采用基本信息/紧凑明细表/实时汇总，签署联系信息默认收起，不新增“款式号”业务控件；选品后完整显示只读产品资料。预览汇总位于同一明细表内，适当合并单元格，保留原240mm及紧凑抬头。查询列表开单日期在第一数据列、编号与类型分列；行首图标展开命中行，不附解释文案；行操作图标有可读名称；销售有扣损时随整单米数展示已存扣损。无需重构业务流程。

**单头汇总字段**

| 字段 | 样布码单 | 销售发货码单 | 定金单 |
|---|---|---|---|
| 总计米数 | 明细米数之和 | 明细毛米数之和 | 明细米数之和 |

2026-10-18用户纠正：撤销此前误记的“定金单应收＝合同金额−定金金额”。定金单仅汇总总计米数、合同金额、定金比例及计算后的定金金额，编辑/预览/PNG/Excel一致。上表为录入与保存字段；沿用已发布打印列：样布含规格与备注，定金打印货号/色号/品名/米数/单价/金额六列（备注仍录入保存），销售打印货号/色号/品名/每组10匹米数/匹数/米数/有值时扣损/单价/金额，不借选品接线增添打印列；销售门幅等产品规格在编辑中只读展示、备注保存。

| V2-10 | 人工补选仅搜索色卡（编号/花型编号/面料品号/品名）；首列编号点击展开/收起，无额外文案，展开为紧凑花型缩略图＋花型编号勾选列表，默认全选；每卡单一“加入”按勾选提交，全选整卡/部分子集/零选禁用，无独立子集按钮；无卡产品不展示也不可绕过接口；写入复核归属、权限/会话/供样条件，保留人工来源与历史 |
| V2-11 | 选样读取最新产品资料，与已保存单据冻结资料分开；移除保留相应历史 |
| V2-12 | 客户通过有效花型 H5 链接免登录查看设计图、面料/细节/效果图及成分规格；不展示价格、源文件、客户或选样资料，不授予内部业务操作权；不另建单产品扫码页或独立客户合集；已发出的链接不支持手动撤回；停用某个配色只隐藏该配色，其余启用配色继续展示；母版停用或没有启用配色时页面提示“暂不可用”；重新启用后原链接恢复展示，无需重新分享 |
| V2-13 | 色卡列表支持多选导出 Excel，每卡一行且严格六列：色卡编号（母版编号－面料品号，如 1234-F018）、品名、成分、克重（保留 gsm/mm 原单位）、门幅（带 cm 单位）、二维码（原始编码纯文本）；二维码 与页面二维码解码逐字一致，不嵌图片/公式，不按配色展开或增列；只导出所选，不静默扩大为全部色卡；管理员与业务员均可导出 |
| V2-14 | 已建色卡不得更换母版或面料品号；改变实物身份须删除后新建。删除使旧卡退出有效集合，旧码永久撤销，历史选样、寄样和扫码事件保留原卡 ID 与来源关联，选样单仅标"已失效" |
| V2-15 | 面料的品名、成分、克重（含单位）、门幅发生实际值变化时，自动把全部有效关联色卡标记"需重新打印"，可筛选可见；字段未变的重复保存不标记，新增或停用配色产品不触发。运营逐卡手动标记"已重新打印"后清除，基于旧资料版本的确认必须失败并保留提醒 |
| SHIP-01 | 选样与实际寄样分别记录；登记寄样日期、产品和数量，支持同一选样单分多次寄出、部分寄出和补寄；已选未寄的产品计入待寄，选样不自动变成已寄 |
| FOLLOW-01 | 登记客户确认、反馈与跟进结果，并安排下次跟进日期；可关联本次选样涉及的产品，供开单时参考，不自动生成单据 |

色卡、分享、寄样及跟进细则见[详细规格](../product-master/product-master-v2-requirements.md)。

## 3. 性能需求

| 编号 | 要求与验收口径 |
|---|---|
| PERF-01 | 花型库、产品库各按约 2,000 条规模验证检索；覆盖一母版多配色、一版本关联多面料、多标签及跨页命中，不能只用少量演示资料 |
| PERF-02 | 在验收时记录的办公设备、网络和部署环境下，常用编号/关键词/标签查询从提交条件到当前页结果可操作，95% 的请求在 1 秒内完成；首次进入和图片加载单独观察，记录端到端时间、后端处理时间与测试环境 |
| PERF-03 | 全库过滤后分页，图片按需加载；不能把全部记录与图片加载到前端再筛选，选择器也需支持快速查找 |
| PERF-04 | 单据和库存随业务量增长时，列表、查询、统计和导出保持可用；不因数据量增加而阻塞操作或整页长时间无响应 |

性能验收细则见[检索与性能](../product-master/product-master-v2-requirements.md#8-检索与快速找款)。单据与库存不设固定量级数字，按 PERF-04 的可用性原则验收。

<a id="reliability"></a>

## 4. 可靠性与数据安全需求

| 编号 | 要求与核验重点 |
|---|---|
| REL-01 | 保存、替换、删除、排序或导出失败明确提示，不能假报成功；产品与关联资料一起保存，失败不留下部分业务修改，原记录仍可使用 |
| REL-02 | 编辑保存失败保留输入；取消不保存本次修改，未保存离开提示。并发修改提示冲突，避免无提示覆盖；相同产品组合的重复/并发创建不得产生重复记录 |
| REL-03 | 内部业务所有读写入口由服务端逐次检查登录身份、动作权限与数据归属，拒绝未登录及越权请求；花型 H5 允许通过有效分享链接免登录读取 V2-12 规定的公开内容，服务端逐次校验链接有效性及公开字段范围，不开放内部业务操作 |
| REL-04 | 产品、图片和身份关联在删除时重新检查引用；配色号永久不复用，退役色卡旧码不复活，重复选样不产生重复有效项 |
| REL-05 | 升级、切换和清理保留历史单据、客户、公司、库存及共用图片；缺失字段不能导致数据清空或全员可见，本地缓存不能覆盖服务器事实 |
| REL-06 | 上传和 JSON 输入执行校验；认证信息、存储凭据与客户敏感数据不得因日志、导出或公开展示而泄露 |

保存与并发约束见[详细规格](../product-master/product-master-v2-requirements.md)，权限及安全见[安全要求](../product-master/product-master-v2-requirements.md#10-权限安全与可靠性)。
