# V2 图片资产运维

> 现行运行边界，核对：2026-10-24。依据 `v2ProductionRuntime.ts`、`v2ImageProcessor.ts` 及 V2 schema；状态见[项目现状](../project/项目现状.md)。本页不授予数据库、COS 迁移或删除权限。

## 正式运行与图片归属

正式启动要求私有 COS 和 `IMAGE_ASSETS_ENABLED=true`，不支持切成本地存储应急；运行时强制开启公司和产品资产链。关闭旧业务开关、先全关再逐步启用不是当前 V2 回退方案。配置、凭据及真实开关由受保护的本机/服务器配置管理，文档不保存值。

`image_assets`、variants、上传会话和处理任务提供共用资产能力。V2 产品引用为 `v2_product_image_assets`，配色通过 `pattern_image_asset_id` 引用资产；公司及历史引用仍需保护。不能只统计旧 `company_image_assets + product_image_assets` 就判定全系统零引用。数据结构取实际 schema，不在手册复制表定义和默认值。

上传会话经服务端解码、类型/尺寸及 SHA-256 校验，客户端不得指定正式 object key 或以声明的 MIME/哈希替代验证。正式 worker 仅处理新图片任务并恢复超时处理任务，不启动旧引用重算或物理回收循环。

## 禁止套用旧维护流程

旧 maintenance/reconciliation/purge 只认识旧关联，可能漏算 V2 引用。**不得对当前 V2 运行旧引用重算、旧自动回收或据旧 ref_count 物理删除 COS 对象。** 资产处于 recycled、时间到期或旧关联为零均不足以证明当前可删。

旧图片迁移、角色迁移和旧批量上传脚本不是现行操作入口，不能从历史手册复制 apply 命令到生产。确需治理时须另行审查所有现行引用、权限和恢复保护，完成独立验证并取得具体操作授权；本次文档收敛未执行迁移、回收或 COS 操作。

原手册的六表定义、开关默认值、迁移示例、每日对账、30 天回收和关闭开关回退描述保存在[仓库外恢复包](../maintenance/文档整合与恢复.md)，只解释旧实现，不能据此恢复旧 worker。发布失败按[统一发布工具](统一发布工具.md)回退受版本保护的程序或切同版本 V2 只读入口，保全新写入和媒体。

## 访问、错误与费用

图片请求保持身份/公开授权、短时签名及共享引用保护。产品三类图片只加载当前类别，同次查看复用；CSS 缩小不减少原图传输量，不能承诺再次打开免费。COS 存储、外网、请求和回源费用按真实地域/合同/账单及当期价格核查，旧报价与估算不作为当前费用承诺。

日志使用 `server/image-assets/observability.ts` 的脱敏规则，保留稳定 requestId/assetId/jobId/errorCode；不得记录密钥、Cookie、完整签名 URL。错误码和 retryable 行为以当前 API 与测试为准，失败时保留原始资料，不通过手工删库/删对象来重试。

真实上传/下载、共享删除拒绝、引用事务、COS 原件及恢复演练分别取得证据；本机替身测试不代替生产验证。旧价格、测试数字和调查流水均按恢复索引查阅，不继续追加在手册中。
