# Fabric 统一发布工具

> 2026-10-24 目录整理：本文部分历史路径对应的临时文件、已退役源码副本或旧发布证据已完整迁至仓库外；原路径作为历史定位保留，按[文档整合与恢复](../maintenance/文档整合与恢复.md)中的范围和逐文件 SHA256 查找原件。未完成的业务 Gate 仍按当前进度保留。

本工具承接已确认的固定流程：变更/源身份检查、一次构建和制品冻结、线上预检、一致性备份及加密离机、必要的恢复演练、迁移、原子安装、验证、失败代码回退。沿用现有 Node＋SSH＋Python，不增加服务或依赖。只检查发布涉及的内容，不默认跑全量测试，不在工具收尾修复历史文档。

固定入口为 `npm run release -- <command>`。配置只维护环境目标，旧版摘要从已核验的发布基线读取；日期和归档摘要由工具生成。详细日志写入每个制品目录，终端只显示阶段、结果和耗时。

普通发布和迁移发布共用同一执行器。迁移必须在代码登记、绑定计划摘要，并通过同一备份的隔离恢复和重复迁移验证。仅回退程序，不将历史SQL覆盖到生产。未知执行结果停止自动重试，通过status核对后恢复。

## 源码批准与 UI 专项

- 取消人工逐条编辑 `source-manifest.json`：运行 `node scripts/release/source-automation.mjs inspect` 查看实际改动，再在人工确认改动文件后运行 `node scripts/release/source-automation.mjs accept <文件1> <文件2>`；只接受与实际变动集合**完全一致**的路径，任何额外改动、需求漂移、文件链接或错误工作区均拒绝，绝不自动批准全部工作区变更。
- 发布成功并验证线上制品之后，`cli.mjs` 自动同步 `docs/project/fabric-v2-active-workspace.json` 的 `currentRelease`。对发布前使用旧发布器而留下的状态差异，可在确认远端版本后执行 `node scripts/release/source-automation.mjs sync-pointer <已验证的发布ID>`；要求 release-result 与私有已验证基线完全一致。不把失败部署误写为上线完成。
- 面料主数据字段/Excel/DB 约束相关代码有改动时，发布准备阶段自动执行面料专项测试，防止预览与数据库约束不一致。
- 只有单独面料列表组件 `FabricLibraryV2.tsx`（以及它的测试）有变动、且已录入源摘要绑定的桌面/手机视觉证明、无数据库迁移时，允许显式 `npm run release -- run --quick-ui`；改为执行组件单测和实际浏览器桌面/手机几何验证，避免无关页面的百秒级完整 UI 套件。其余 UI 变更仍默认运行完整 `test:ui:ux`。不是免测试通道。
- 发布工具自身新增保护性单元测试，验证源码改动白名单、指针只在发布成功后更新、快速 UI 的精确适用范围；生产备份、异地读回、需要时的恢复演练、原子部署、线上核验和失败保护全部保留。

## 使用

在唯一项目根目录 `D:/fabric` 执行。

```powershell
npm run release -- plan
npm run test:release
# 首次安装或恢复本地发布状态时，以已发布证据核对现场后初始化；不盲目接纳线上漂移。
npm run release -- baseline --evidence artifacts/releases/RELEASE_ID/release-result.json
# 普通发布，一次构建后贯穿所有必要步骤。
npm run release -- run
# 先准备再查看/演练，不发布；ID由prepare输出。
npm run release -- prepare --migrations card-share,light-customers
# 工具演练复用当前已上线制品；要求当前server/src与发布源一致，不重新构建应用。
npm run release -- prepare --from-release artifacts/releases/RELEASE_ID/release-result.json --migrations card-share,light-customers
npm run release -- preflight RELEASE_ID
npm run release -- rehearse RELEASE_ID
# 真正执行发布：复用该ID，不再次构建。
npm run release -- deploy RELEASE_ID
npm run release -- verify RELEASE_ID
npm run release -- status RELEASE_ID
# 本地耗时报告，不连接生产。
npm run release -- report RELEASE_ID
npm run release -- resume RELEASE_ID
npm run release -- rollback RELEASE_ID
```

`prepare` 和 `plan` 不访问生产；`preflight` 上传固定制品、核对线上版本/物理数据库/PM2/恢复服务并执行登录读取，不切换程序；`rehearse` 在此基础上备份、加密离机校验、恢复到唯一隔离库并检查登记迁移，最后仅删除本次新建的演练库。`run`/`deploy` 会迁移并切换生产，必须处于用户已授权发布的任务中使用。`verify` 仅验证已经安装的版本，`status` 仅读取远端状态，`report` 仅读取本地耗时证据，三者不会隐式发布。

已成功阶段不会重复执行。失败时保留日志，通过 `status` 查看服务器回执；`resume` 明确恢复，可安全重试的只读/传输步骤复用原制品。服务器标记为“正在执行”且结果未知的备份、迁移安装或回退不会盲目重试，应先检查证据并完成受版本保护的回退或人工收敛。已回退制品不能再次发布，需要新ID。

## 配置和证据

- 环境配置：`scripts/release/production.json`，只保存固定目标、进程和数据库身份；无密码或密钥。
- SSH沿用 `.local/server/_config/ssh.local.json` 和既有主机密钥校验。发布基线及离机备份口令保存在其旁的私有 `release-state` 目录。
- 每个制品：`artifacts/releases/RELEASE_ID`，保存 `run.json`、固定manifest/归档、构建/远端日志、加密备份、离机校验、阶段耗时；成功发布产生标准 `release-result.json` 并更新已验证基线。
- 远端也保存各阶段回执；制品和执行器均按SHA固定，后续工具更新不影响使用旧制品内的执行器回退。
- 新迁移在 `scripts/release/migrations.ts` 登记，更新 `core.mjs` 的允许ID并补充相关测试。当前开放已演练的色卡分享、客户档案、客户V1.2三项迁移（V1.2含受精确保护的单列容量扩展）；不允许从JSON注入任意SQL或shell。需要改变既有表结构的迁移应补充相应保护和专用演练，不能绕过现有旧列保护。
- 默认执行源身份检查、完整HTTP合同检查和完整构建，业务专项测试由开发阶段完成；`test:release` 仅跑发布工具的行为/故障测试，不跑业务全量测试。HTTP验证不代表浏览器或微信人工签收。

## 维护边界

今后正常发布使用此入口；既有日期脚本保留为历史证据，不作为默认发布入口，不再复制生成下一套日期脚本。只在变更影响发布器时运行 `test:release`；业务变更不应反复修改发布器。源码、环境或制品漂移立即停止，先查明确切差异。

`--from-release` 只接纳与本地已核验线上基线完全一致的已发布归档，并核对归档、真实首页/后端、浏览器文件和源清单摘要。当前server/src代码还要与该源清单一致，才能检查复用制品的HTTP合同；不会把未审阅的新代码伪装成已验证制品。正常的新业务发布仍须走源码门禁和构建。

## HTTP 合同、失败恢复与验证边界

`prepare` 在应用构建前启动完整正式 HTTP 装配，以固定测试身份检查退出路由和匿名拒绝，不读写真实数据库。`http-contract.json` 随制品摘要冻结，供本地与远端使用；旧路由误返回 404 而非合同要求的 410，应在上传前失败。HTTP 合同检查不代替业务、浏览器或微信验收。

远端失败即使以非零退出，也应将自动回退回执保存到本地；断线后先查询状态，确认回退的 ID 不得再次发布。`report` 仅统计真实非重叠阶段，缺失的历史耗时不补造，不能把复用准备或排除等待后的累计值当作完整开发提速。
