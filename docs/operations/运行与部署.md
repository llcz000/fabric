# Fabric 运行与部署

> **现行运维入口**。实际发布命令统一使用[统一发布工具](统一发布工具.md)；过时的按日期脚本和旧控制器双目录不再适用。发布必须有用户明确授权，本文件不授予部署权限。

## 本地

从单根 `D:/fabric` 安装依赖并运行 `npm run dev`。实际生产/测试凭据在本机受保护配置和 `.env` 中，不能写入知识库。构建运行 `npm run lint`、`npm run build`，按需要运行 `npm run test:unit`、`npm run test:security` 或 UI 专项。当前 `server.ts` 只接受 V2 生产目标，配置不成立会拒绝启动，不再回退旧JSON/legacy应用。

## 发布工具固定流程

先运行 `npm run release -- plan` 了解阶段；本地离线工具验证为 `npm run test:release`。业务源码修改后，受控查看并批准源码集合的工具是 `node scripts/release/source-automation.mjs inspect` / `accept <精确文件>`，不能自动批准整个工作区。只有得到当前用户授权、目标数据库/服务器身份明确且备份可恢复，才能按冻结制品和发布计划执行发布。未知远端阶段结果只用原版本 `status` 核对，不自动重复重部署/迁移。

发布阶段必须验证：确切源SHA与生产旧版、目标MySQL身份/列约束、不可变制品、加密异地备份、必要的恢复演练、远端切换、`/api/health`/业务状态/鉴权、公网可信TLS及失败回滚。HTTP 200 或PM2在线不能单独视为成功。实际结果以 `artifacts/releases/<ID>/release-result.json` 等可验证原始证据为准。

## 数据与环境保护

客户/图片/导入源文件、`uploads/`、`template/`、`.env`、`.local/`、发布制品和旧生产备份绝不随知识库清理删除。MySQL主路径、图片COS、跨库FK/事务和真实浏览器/微信测试分别检查。图片资产迁移/回收详见[图片资产运维](image-asset-operations.md)。

最新系统状态参见[项目现状](../project/项目现状.md)，CI与上线审批参见[远端构建和发布Gate](fabric-v2-remote-build-and-deploy-gates.md)。
