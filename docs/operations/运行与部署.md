## 本地运行

1. 安装依赖：`npm.cmd install`。
2. 从 `.env.example` 创建本地 `.env`，设置随机 `ADMIN_PASSWORD`，按需配置 DB/COS 与功能开关。
3. `npm.cmd run dev`；默认访问 http://127.0.0.1:3000。
4. 生产构建：`npm.cmd run build`；设置 `NODE_ENV=production` 后 `npm.cmd run start`。

缺少 ADMIN_PASSWORD 会拒绝启动；当前 token 期限为 12 小时，并提供退出撤销。默认登录失败限流 15 分钟 10 次，普通 API 1000 次；健康检查绕过业务限流。配置和实际参数以 server.ts 为准。

## 发布前检查

- 明确目标版本、本地改动与远程运行版本；确认配置、权限、备份和回退路径。
- schema 在实际目标 MySQL 版本及权限下，以空的隔离结构演练全新、部分完成、重复运行。
- 当前产品 schema DDL 仍存在已知兼容性问题，详见[部署失败复盘](../retrospectives/development/2026-09-26-product-schema-deployment.md)。未完成修复与真实演练不能以历史测试计划代替。
- 代码提交/推送、线上部署、正式数据导入是独立动作，按用户授权分别处理。

## 发布后与失败处理

同时核对目标提交、构建/进程状态、`/api/health` 的 `storage=mysql`、关键表列索引和真实业务 API。HTTP 200 / PM2 online 只证明相应存活状态。数据库初始化失败、存储意外切为 JSON 或业务 API 出错时判失败，按回退路径恢复并复核，不继续业务导入。

## Fabric V2 程序增量发布的最小标准流程（2026-10-20）

> **已验证的发布经验，不是现成的自动化部署工具。** 当日两次脚本误判/一次回退后最终已上线的实际证据见[正式增量发布](2026-10-20-pattern-bulk-release.md)，详细故障根因和待办见[发布效率复盘](../retrospectives/development/2026-10-20-pattern-bulk-import-delete.md#2026-10-20-发布效率专项复盘两次误判重复发布和未固化流程)。下列 `plan / verify / apply / status / rollback` 是**拟建设的统一 CLI 接口**，不是声称今天可运行的命令。当前仍按审批过的实际发布脚本执行。

**选用场景：** 已有正式V2、无数据库DDL、仅程序和版本化静态资源变更；有迁移、旧系统切流、真实 COS/业务数据操作时另走独立高风险 Gate，不直接套用本流程。真实发布仅在用户授权、生产部署通道允许且所有保护到位后执行。禁止为了加速跳过DB快照、身份核对或可恢复性要求。

| 阶段 | 必要动作/停止条件 | 应生成的单一证据 |
|---|---|---|
| 1. 固定范围 | 选定**唯一活动源码**、当前需求版本、上次真实已发布的前后端 SHA、允许变动的源路径；脏Git工作树须逐文件审查，禁止全量add/reset/覆盖。先判断静态only / 程序无DDL / 含迁移三类 | 来源/差异/基线清单、风险类型 |
| 2. 一次性质量 Gate | 串行相关测试、TypeScript、安全、图片契约和最终构建；生成并**冻结同一个SHA-256发布包**。发布脚本变化不重新改编应用源码，不必无故再次全量测试；如应用包变动则重验 | 测试结果、准确制品 SHA、文件 manifest |
| 3. 完全只读预检 | 在**换文件之前**实核线上版本 SHA、MySQL目标UUID/schema、PM2/NGINX、登录/现有业务读取、3009只读。对 `/api/runtime` 真实生产返回运行同一契约判定器及负向样例；不匹配则停止，严禁猜测字段 | Preflight 通过/失败及差异 |
| 4. 备份并验明可回滚 | 冻结旧首页/后端、必要MySQL一致性备份并逐项核对摘要与压缩完整性；涉及schema/媒体/重要业务则必须有经批准的恢复演练及离机副本 | 备份路径、摘要、恢复边界和责任人 |
| 5. 受控切换 | 校验远端同一制品SHA、使用单一发行锁，安装不可变静态资源，原子替换后端；仅对已批准的正式PM2重启。若需维护窗口先通知；禁止意外修改启动器、NGINX、只读worker或数据表 | 切换时间、版本摘要、PM2新PID |
| 6. 快速验活或回退 | **同一**状态判定器检查旧版/新版切换及回退：可写端 `mode=v2`，且 `readOnly` 字段**缺省或显式布尔 false**；只读恢复端必须 `readOnly:true`。非JSON/错误字段类型/请求超时/健康返回storage非mysql/关键读取失败都判失败；程序回滚前确认未被其它版本覆盖，回退后照同一合同验旧版 | 首次健康时间、回退状态与归因 |
| 7. 独立公网和功能验收 | 走默认可信TLS校验精确HTML/JS/CSS摘要、匿名写入401、旧API预期410、管理身份读；任何真的业务导入、删除或COS写入只在授权隔离数据/预发布环境演练 | 第二阶段公网结果、已测/未测业务范围 |
| 8. 自动闭环 | 只维护一份运行日志和一份脱敏结果JSON，附环境、旧/新SHA、备份、错误、开始/结束UTC时间及待验Gate；在唯一进度文档更新上线状态，复盘索引只增加可复用的新根因 | 版本状态、证据链接、效率测量 |

**运行状态契约防误判的核心示例：** 写端实际可能返回 `{"mode":"v2"}`；字段缺省**不能**写成 `get('readOnly') is False`；推荐共享判定逻辑为 `mode == 'v2' and ('readOnly' not in result or result['readOnly'] is False)`。读端要求 `result.get('mode') == 'v2' and result.get('readOnly') is True`。两个判断都需先验证HTTP 200、JSON对象结构，且异常类型必须拒绝；在切换前把这两份**实际响应**和 true/错误类型/模式错误用例加入脚本自测。上线脚本、回滚脚本与公网核验禁止各写一份相似而不一致的判断。

**提升效率的红线与指标：** 追求的是“预检阻断有问题的发布，生产只尝试一次”，不是减少必要风险保护。首次落地以每次记录制品准备/测试/预检/授权等待/备份/切换/首次健康/公网上线/关闭的独立耗时为准；连续5次无DDL发布后再定实际分钟SLO。建议今后统一版本化Release CLI、自动化测试和审批式制品发布；当前文档只记录规则，CLI/CD与可恢复演练仍属于**待开发/待验收**，不可误报已实现。
