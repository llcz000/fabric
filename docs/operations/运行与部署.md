# 运行与部署

> 文档定位：规范与手册｜主要读者：设计/开发/测试/运维及Agent。用途：按当前任务选择对应规范或运行方法。

更新：2026-10-09。运行命令来自 README / package.json；远程环境没有在本轮重新检查。

## 本地运行

1. 安装依赖：`npm.cmd install`。
2. 从 `.env.example` 创建本地 `.env`，设置随机 `ADMIN_PASSWORD`，按需配置 DB/COS 与功能开关。
3. `npm.cmd run dev`；默认访问 http://127.0.0.1:3000。
4. 生产构建：`npm.cmd run build`；设置 `NODE_ENV=production` 后 `npm.cmd run start`。

缺少 ADMIN_PASSWORD 会拒绝启动；当前 token 期限为 12 小时，并提供退出撤销。默认登录失败限流 15 分钟 10 次，普通 API 1000 次；健康检查绕过业务限流。配置和实际参数以 server.ts 为准。

## 发布前检查

- 明确目标版本、本地改动与远程运行版本；确认配置、权限、备份和回退路径。
- schema 在实际目标 MySQL 版本及权限下，以空的隔离结构演练全新、部分完成、重复运行。
- 当前产品 schema DDL 仍存在已知兼容性问题，详见[部署失败复盘](../retrospectives/development/2026-09-26-product-schema-deployment.md)。未完成修复与真实演练不能以历史测试计划代替。
- 代码提交/推送、线上部署、正式数据导入是独立动作，按用户授权分别处理。

## 发布后与失败处理

同时核对目标提交、构建/进程状态、`/api/health` 的 `storage=mysql`、关键表列索引和真实业务 API。HTTP 200 / PM2 online 只证明相应存活状态。数据库初始化失败、存储意外切为 JSON 或业务 API 出错时判失败，按回退路径恢复并复核，不继续业务导入。

## 运行数据与本机配置

`.env`、uploads、template、database_fallback.json、导入报告/备份都不是通用知识，不作为文档清理对象。本机 SSH 与环境基线保存在 `.local/server/_config/`，原本机敏感文件隔离于 `.local/legacy-sensitive/`，这些路径已忽略 Git；知识库不收录其内容。
