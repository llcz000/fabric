### 客户选择与选样导出

- 选样 Excel 日期应使用与列表同源的创建时间戳，以北京时间计算。生产 MySQL 会话已在北京时间时，再以 UTC 为来源转换会重复偏移。定向用例以北京时间零点前后的相邻时刻校验输出日期。

- 调整选样 Excel 模板时，应在全部导出用例中搜索旧表头、列数和模板描述。仅按“核对”或“批量”筛选会遗漏列表直接导出及明细整单导出。正式发布已实际拦截这两处旧六列断言，须补齐场景后重试，不能以更改少量断言为由省略受影响入口。

- 已经保存的选样联系人姓名无法单独证明人员身份。选样与客户档案采用稳定联系人标识，历史姓名仅在档案修改前有唯一匹配时绑定。回归覆盖同公司两位联系人、改名后的搜索及删除后同名重建隔离。批量 Excel 用同一色卡跨单重复的用例核对工作表数量、归属列和数据行数；先鉴权整批，再返回核对提示。证据与待验收范围见项目现状，归档不适用。

- 公司档案的全部联系人无法说明某张选样单是谁选的。普通建单和首扫共用联系人选择，保存本单姓名快照，档案索引选择同时核对档案版本，编辑同时核对本单关联版本。旧单无证据保持未指定，补录只修改本单联系人。回归同时核对跨人独立、权限、取消及保留原配色。实际证据见项目现状，历史约束保留，归档不适用。


- 精简人工补选入口时同时核对扫码后看图选款与保存后明细，两者应复用同一搜索和勾选行为。用完整色卡编号验证单一入口，再核对搜索失败重试、Esc 焦点回归及正常扫码加入。 删除入口前应在全部浏览器 spec 中按旧文案和扫码令牌查找引用，包括用例名未出现“补选”的首单场景；更新断言后先定向验证，再进入全量发布门禁。当前证据见项目现状，历史技术约束保留，归档不适用。

- 客户改名后，用稳定客户 ID 读取选样列表、明细和客户业务历史的当前展示名，列表筛选与展示用同一口径。原名快照供追溯与存量回退。改名校验在服务端保存事务中执行，校验失败返回专用冲突码，让用户能在原表单修改草稿后重试。定向回归已复现并验证；当前状态见项目现状，历史约束保留，归档不适用。

- 发布全量回归也要同步旧“禁止排序”断言，改为仅编号可排序的新边界，并保留原搜索/列宽/操作间距验收；本轮两条旧断言修订后定向及完整95通过/2既有跳过，无删用例。列表编号排序必须在服务端筛选后、分页前执行；不能以sortRows(page.items)冒充全库排序。按花型数字/配色数字比较、跳过面料品号，等值项加稳定ID，不改变身份或折叠行；手机信息块隐藏thead时须另留可达排序入口。客户删除前的关联数量只是预览，实际DELETE仍在客户更新锁内检查未删选样，与创建选样使用同一客户锁；旧“已删客户仍有选样”的兼容测试应种入存量数据，不再调用受保护的新删除API构造。联系人只投影授权档案姓名，字段文案调整保留region原值。已观察删除保护/编号排序/联系人失败测试后修复，桌面和360px真实浏览器检查覆盖；旧导航测试浏览器替身缺失dispatchEvent会引起连锁卸载错误，应补齐真实事件契约，不放宽产品行为。历史约束保留，归档不适用。

- 历史记录的编辑只读与独立删除必须分别建模。客户逻辑删除后，沿用 canEdit 作为选样 canManage 会同时误隐藏更多菜单、阻断删除；应保留客户与授权共享锁、链接一致性及选样更新锁，以当前管理员/负责人/编辑授权计算 canDelete，所有其它编辑门禁不变。已在SQLite真实事务验证拥有者/管理员/编辑授权、仅查看/无权/撤权、旧grant防绕过、审计失败回滚及明细/反馈保留，并在1440/360浏览器验证确认取消/失败重试；生产验证只读，不为验收删除客户记录；本轮部署后真实API确认用户指定三单canDelete=true且canManage=false，发布回执及当前版本以项目现状为准。历史技术约束保留，归档不适用。

- 搜索列表以规范化关键词驱动时，不能在仅空格变化的输入事件中先清空结果，否则关键词未变、请求不会重跑，已有客户会消失并诱导重复建档；用真实浏览器覆盖末尾空格与错误重试。
- 将新建入口改为条件渲染子页面时，要逐条检查能力开关分支的离页保护；主分支子组件注册了保护，不代表兼容分支也有，延迟提交期间必须阻止离开。
- 为目录新增关联计数，要同步测试数据库中的关联表和时间函数适配；用实际SQL执行验证去重、已移除项和跨单隔离，不以固定计数替身代替。
- 按单Excel导出从服务端当前授权及选样来源推导范围，复用已有Workbook格式；不能信任客户端勾选ID，也不能复用列表单页作为完整导出集。

- 选样状态与入口调整后，SQL替身必须匹配当前锁查询，真实HTTP测试不得因替身漏读而把503当业务拒绝；重扫保留主动取消，恢复走明确补选，固定签字栏不再断言旧配置文案。全量检查应先排除生成制品，不能只给定向结果。已有经验保留，当前状态与发布回执以项目现状为准，无文档归档/清理。
- 发布前浏览器回归会重写通用截图路径；截图须等待能力/加载态就绪，审查时再复制到候选专属路径并核对SHA，冻结包只引用该路径，不能让后续测试覆盖已审证据。
