# UI交付与用户改稿：保留字段、当前状态和视觉证据

> 文档定位：复盘经验｜主要读者：开发、测试/评审、Agent。用途：遇到同类问题时读根因、做法和验证范围。

2026-10-15提炼；原事件2026-10-11～14。读者：UI设计/开发、评审、Agent。适用于继续既有设计、Stitch或React评审任务；2026-10-14起Stitch按需使用。

| 问题/根因 | 提炼后的做法 |
|---|---|
| 远程产品备注列被旧“11列”提示覆盖 | 开改前对照上次同步稿、最新远程HTML/截图和本轮要求；保留用户独立修改，产品12列备注在图片数量后。数量/ID正确也可能丢字段，交付检查要含受保护列 |
| 已生成保存稿却未挂画布，工具成功事件无实质变化 | 生成对象、画布实例、实时视觉、用户批准分别登记；重新下载HTML/截图检查实际结果，不能把DomOperationEvent或保存稿ID当画布已交付 |
| 只登记生成页，漏掉用户要求的独立页面 | 开工先列全部预期页；逐页核身份、HTML/截图/真实画布；连接超时保留未验，不补造截图或删除未核验旧稿 |
| 旧摘要的五/七页、待审/批准互相冲突 | 状态只在当前进度维护；批准绑定具体版本与对象。恢复上下文先读进度/差异，不重开已批准规则，也不让旧快照盖新要求 |
| 页面自带角色、Pantone身份/审批/标签尺寸变成新需求 | 工具输出只是建议，必须对照PRD；不恢复已取消多母版/单产品二维码，不混淆产品货号与色卡编号 |
| B3离线移除/撤销演示被误当真实后端 | 离线DOM、React/API、真实MySQL和手机扫码分别验；v1.50资料按最新主数据回读，旧快照交互仅历史证据 |

12列恢复曾对实际新旧HTML及哈希核对，问题是未合并用户字段，不是Stitch无法读取。后续浏览器超时仅标未验证，未绕过限制。现行操作见[UI规范](../../ui-design/README.md)和[流程第8节](../../product-master/product-master-v2-ui-iteration-workflow.md)；历史UI依据集中在[UI评审专题](../../product-master/product-master-v2-ui-review.md)。
