# 同一HTTP状态流：权限、冻结单据与共享图片经验

> 文档定位：复盘经验｜主要读者：开发、测试/评审、Agent。用途：遇到同类问题时读根因、做法和验证范围。

2026-10-15提炼；原事件2026-10-13/14。读者：集成开发、测试/评审、Agent。用于模块都通过但组合入口仍出错的情形。

## 关键根因与做法

| 问题 | 原因与可复用做法 |
|---|---|
| 独立Router通过，统一入口仍404 | 模块存在不等于装配；用实际Express统一入口验证可达、JSON安全错误与同一账号的两项独立权限，撤权后重试 |
| 旧P6/P3各一套产品删除行为漂移 | 收口单一核心算法；事务内重查权限/引用，已开单用停用入口；物理删除不能绕过媒体账本 |
| 已保存单据与删除引用测试假阳性 | 同一个状态化数据库先POST三单据→GET冻结值→再DELETE产品；不为任意产品ID固定返回引用1。明细编辑保留ID与原快照，不放宽销售分匹规则迎合测试 |
| 已开单产品删图计数被动过 | 引用拒绝必须在任何图片DML之前；另测已扣账后FK竞态和图SQL故障，ROLLBACK恢复完整产品/关联/资产对象，两条路径都要 |
| 共享资产被误回收 | 创建两个产品确实使用同assetId，开单锁一个、删另一个，断言2→1仍ready与独占1→0回收；不直接删共享资产/COS |
| 故障信息外泄 | 异常从统一API验证安全503/400/413 JSON；不能按不可信驱动错误前缀决定原样回传 |

## 真实范围

历史真实回环HTTP使用原业务服务与状态化SQL替身；三单据状态流4/4曾通过。不证明InnoDB真实并发/FK、COS对象删除或30日时间到达；缺真实授权/写入、正式App/性能/备份回滚时仍不能上线。原始B2-4在途红测不由本任务改动，最终统一回归须等冻结代码。
