# 2026-10-20 花型整删与批量图片导入

## 触发条件与根因

用户要求花型库列表支持删除整花型，并批量导入按“花型母版号-配色号”命名的图片（例如 `G0008-1.jpg`）。原有母版 DELETE 接口即使子配色完全未引用也拒绝删除；原有“创建下一配色”只能自动分配编号，不能安全接受导入文件里指定的正整数配色号。

## 处理与边界

- 对整个花型执行前端二次确认，后端在一个事务中锁定母版及配色、拒绝关联产品/任何状态色卡、逐版解除图片引用及回收零引用资产，最后删除配色及母版。数据库外键仍为最终保护。
- 批量导入先对文件名、MIME、20MB 文件大小、正整数、重复键做客户端校验，按母版及数字序号升序处理；上传完成后由新增 `POST /api/v2/pattern-catalog/import` 在单个事务里匹配/新建母版、创建指定编号配色、关联已就绪图片并前移永久序号。
- 拒绝覆盖既有配色或重新使用曾分配的编号；每张图片独立反馈成功/失败，不对可能已提交的请求自动重试。上传已成功而关联失败的零引用媒体需要在真实 COS 回收链路验收中检查，不在失败时贸然删除共享媒体。
- 保留本工作区其他正在进行的修改；未连接真实生产 MySQL/COS，未执行业务导入/删除，未提交/推送/发布。

### 可复用规则（先防二次失败，再加速）

1. **P0｜共享可写/只读运行状态契约，先离线验证。** 为正式 `/api/runtime` 定义清晰 Schema：可写要求 `mode=v2` 且 `readOnly` **缺省或显式 false**；只读必须**显式 true**；错误类型、缺少 mode、非 JSON 和异常 HTTP 都拒绝。采用**同一个判定函数**覆盖前置、重启、上线验收、自动回滚后的健康验证。加入真实响应 fixture、只读/未知值负向用例和离线 PM2/HTTP 模拟故障回退测试；部署脚本在服务器程序未替换前必须能完成只读 dry-run。
2. **P0｜把 `tmp/` 一次性发布脚本变成版本化、受审查的统一 Release CLI。** 最少支持 `plan`（只读变更/影响面）、`verify`（校验发布包、线上 SHA、环境和权限，无任何正式写入）、`apply`（批准后才备份和切换）、`status`（读取结果，识别未完成/已回退，防同包重复执行）、`rollback`（精确版本和最近一次备份白名单）。正式脚本、模板和测试**进入 Git 审核**，参数通过固定目标配置，不在代码中散布日期/IP/PM2 名、旧SHA/路径。
3. **P1｜一次验证、一次制品，禁止到处临时重编译。** 在唯一当前开发工作树生成精确源改动白名单（含未提交内容时单独保存不可变源补丁/hash审计）、串行全量质量 Gate 后冻结含 manifest/SHA/依赖与需求版本的制品；部署、回滚、独立公网复验只引用同一不可变归档。代码无改动时不习惯性重跑全套，脚本变化只补脚本自测/预演；若更换制品，重新执行受影响 Gate 并显式审查。
4. **P1｜按变更类型分级门禁，不混淆质量与生产安全。** 静态资源、无DDL的前后端、含迁移/数据修改三类使用不同且预先批准的流程；前两类仍必须线上旧SHA一致、MySQL实例 UUID/健康/必要业务读、程序备份和可回退、登录与权限负向检查及公网 TLS 哈希校验。含数据库/COS迁移需独立人工审批、恢复演练、数据保护和真实隔离业务往返，不能升级为自动无条件执行。
5. **P1｜把烟测整理为可复用的两段。** 切换后第一段只检查实际新后端摘要、`/api/health`(mysql/v2)、`/api/runtime`、登录/关键目录读取/无效写拒绝和3009恢复状态；失败立即回滚。第二段再批量核对所有公网JS/CSS SHA、更多业务读和安全拒绝，生成**一份**含时间、每项结果、差异和未验业务写入的发布证据。保留生产不可破坏烟测、真实 COS/整删只在隔离夹具中验。
6. **P1/P2｜持续统计发布效率，才可以量化优化。** 每个 Release 记录创建制品→预检→批准→备份→程序切换→首次健康→外部验证→闭环的UTC时间戳，区分运行耗时/等待耗时；统计：总发布时长、部署重试数、回滚数、误报数、离线预检拦截数、停机时长及未完成业务 Gate。建议第一阶段内部目标为**常规无DDL增量只切换一次、同一源码全量质量验证一次、人工可复核且自动生成报告**，基线积累5次以后再设置实际分钟SLO。
7. **P2｜建立审批式 CI/CD 与受控发布工件仓库。** 已有 GitHub Actions **CI-only**，不能谎称已接CD。先固定精确 Git commit/签名源差异、CI生成制品及制品生命周期，再在不暴露生产 SSH/DB/COS 凭据的前提下提供独立授权的部署通道、权限隔离和操作审计；审核前禁止自动生产部署。处理远程工具安全拦截要走许可的运维方式，不绕过拒绝。
