# 数据库可信目标：连接漂移与只读证据经验

> 文档定位：复盘经验｜主要读者：开发、测试/评审、Agent。用途：遇到同类问题时读根因、做法和验证范围。

2026-10-15提炼；原事件2026-10-14。读者：数据库/后端、安全评审、测试、Agent。用于授权读取与写入目标不一致、结构检查误放行或实库验收混淆。

| 触发与根因 | 必须保留的做法 |
|---|---|
| 两个适配器配置看似同库，实际身份不同 | 查DATABASE()/@@server_uuid对照独立声明目标；连接释放和拒绝发生在业务前，驱动异常是不可信文本，不按消息前缀决定透传 |
| 启动首条连接正确，后续池连接漂移 | 每次借出的实际物理连接先核身份再BEGIN；后续认证/owner/业务读也从受保护池取连接、同连接核验后查询；只保护写库仍可越权读 |
| 结构名字存在但含义错误 | CHECK要ENFORCED=YES；FK的引用目标/删除规则、复合唯一、类型/NULL和生成列表达式业务语义都要核对；反向CASE即使列/索引存在也不能放行 |
| 真实MySQL空库HTTP被宣传成完整E2E | 空账号只支持匿名/伪token/错误登录负向验收；表存在不能代替正向授权、真实保存、并发与回滚；禁止造正向结果冒充真库 |
| 只读脚本可能误连或越界 | 固定允许库/实例身份、14表白名单、每表0行先核；失败不继续深查。只允许SELECT/元数据，事务和DML硬拒绝，普通单测默认不连接远端 |

本机RED→GREEN能证明运行期漂移被拒绝，真实只读INFORMATION_SCHEMA能证明当时结构，二者不相互替代。元数据探针/池调度开销、真故障切换、目标MySQL写链及端到端P95、COS、迁移/备份/回滚仍待验。

过程与真实范围见[连接池专题](../../product-master/product-master-v2-p7-local-http-assembly.md)、[MySQL只读专题](../../product-master/product-master-v2-p7-local-http-assembly.md)。
