# Fabric 项目文档

日常只看两份：

1. [项目需求总览](project/项目需求总览.md)：从业务场景与流程进入功能、性能、可靠性要求；只规定做什么与验收判据，页首可按功能直达具体条目。
2. [项目设计开发验收进度](project/项目现状.md)：全项目功能状态与开放事项；V2的阶段明细从这里进入。

开发、测试和 Agent 接手时读[项目设计](project/项目设计.md)：怎么实现、谁实现、按什么切片派发。

[产品主数据V2需求](product-master/product-master-v2-requirements.md)只规定该模块及关联业务的阶段新增/替换需求，不代表全部项目需求，也不取消其中未提及的既有功能。

开发接手再按需打开[阶段任务与源码定位](product-master/README.md#阶段任务快速定位)，不要默认通读历史过程。

| 其他问题 | 按需资料 |
|---|---|
| 架构、尚未完成的设计与批准依据 | [设计与计划](decisions/README.md) |
| 界面规范、开发验证、部署维护 | [UI规范](ui-design/README.md)、[开发规范](development/开发与验证规范.md)、[运行部署](operations/运行与部署.md) |
| 某类问题的根因和防复发 | [经验检索](retrospectives/README.md) |
| 查关键词或完整保留目录 | [文档分类与检索](文档分类与检索.md) |
| 找旧原文、备份与恢复办法 | [清理与恢复记录](maintenance/2026-10-15-项目内容清理.md)、[归档规则](maintenance/知识维护规则.md#任务完成后的强制归档-gate) |

需求只维护业务，进度只维护当前状态，长期技术资料只保留实现约束和必要证据；旧过程原文经提炼、修复引用、备份及归档预检后移出日常目录。源码、客户数据、用户设计稿及验收素材不随文档整理删除。
