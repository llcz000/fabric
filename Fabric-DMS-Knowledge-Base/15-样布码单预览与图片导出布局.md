# 样布码单预览与图片导出布局

## 结论

样布码单的页面预览、PNG 导出和打印应共用同一套“固定纸张布局”。数据表是宽度和右边界基准；公司名称、地址、电话和日期不应根据导出画布或手机视口重新排版。

2026-08-24 完成修复、代码审查、自动化验证和真实桌面/手机视口验证；提交 `5054eea` 已推送至 `origin/master`，后续部署验证已由用户确认通过。

## 原始现象

- 页面预览中，公司信息可以与数据表右边界对齐。
- 点击“生成图片”后，公司信息被推到更靠右的位置，导出画布宽于数据表。
- 手机视口下，日期受响应式断点影响，会离开右侧并另起一行。
- 导出流程另外修改签字区的 DOM 样式，与页面布局形成两套规则。

## 根因

### 1. 导出克隆被强制设为 900px

`DocumentPreview` 页面本身使用 `width: min-content`，固定像素的数据表列宽决定纸张内容宽度。导出时却将克隆节点和容器都强制为 `900px`，公司信息的 `flex-1 text-right` 因此对齐到 900px 画布右边，而不是数据表右边。

### 2. 媒体查询依赖浏览器视口

克隆元素宽度即使是 900px，Tailwind `sm:` 媒体查询仍以浏览器视口为判断依据。手机上会继续命中 `flex-col`、较小字号和较小内边距，导致预览、导出和桌面端纸张样式不一致。

### 3. Flex 子项默认 `min-width: auto`

长公司名、长单号或长客户名可能撑宽纸张。仅设置 `text-align: right` 不能保证边界对齐；可收缩区域必须显式使用 `min-width: 0`，并定义安全换行规则。

## 最终布局决策

1. **数据表是唯一宽度基准**：纸张容器保持 `min-content`，表格固定列宽决定内容宽度。
2. **纸张内部不做响应式重排**：内边距、标题字号、元数据行和签字区间距不再使用 `sm:` 切换。
3. **日期始终在右侧**：元数据容器固定为水平 `flex` 布局；日期使用 `white-space: nowrap` 和 `flex-shrink: 0`。
4. **左侧元数据可收缩**：单号和收货单位容器使用 `min-width: 0` 和 `word-break: break-all`，长文本不撑宽表格。
5. **手机端只负责查看适配**：外层提供 `overflow-x-auto`，纸张内部保持桌面排版，生成后的图片可按屏幕宽度缩放预览。

## 导出逻辑简化

保留必要的图片资源准备、Blob URL 生命周期、取消、超时和错误处理。布局处理收敛为：

```text
页面 print-container（数据表决定 min-content 宽度）
  → 替换受保护的 Logo/二维码为可捕获 Blob
  → 克隆节点
  → 离屏 fit-content 容器
  → html2canvas-pro
  → PNG
```

已删除：

- 克隆容器和单据节点的强制 `900px` 宽度。
- 导出时对 `.signature-section` 及二维码顺序的二次 DOM 查询和样式改写。

## 测试执行器竞态修复

`scripts/run-ts-tests.test.ts` 会在测试中嵌套启动 `scripts/run-ts-tests.mjs`。两个进程共用 `tmp/tests` 输出目录，嵌套进程启动时会删除父进程已生成的测试文件，造成偶发 `MODULE_NOT_FOUND`。

修复策略：

- 先完成请求路径检查和测试文件发现，非法输入不创建编译目录。
- 每个执行器通过 `mkdtemp` 创建独立 `tmp/tests-*` 目录，嵌套进程不再命中父进程输出。
- 编译、子进程启动和测试执行放在 `try/finally` 中，等待子进程 `close` 后使用有限重试清理本次输出目录。
- 回归测试覆盖“嵌套运行不删除父输出”、“成功嵌套运行不残留自身输出”和“失败嵌套运行仍清理输出”。

验收：`npm.cmd run test:unit` 不再拆分执行，单次 217/217 通过；结束后无 `tmp/tests*` 目录残留。路径逃逸防护测试需要在项目根目录之外创建并清理临时目录；受限沙箱中仍需单独授权。如进程被操作系统强制终止，JavaScript `finally` 无法保证执行；独立目录仍能保证残留不会破坏其他并发测试。

## 后续建议

- 如新增 PDF 或其他单据导出形式，继续复用同一个纸张 DOM，不再建立导出专用布局。
- 如增加端到端测试，优先覆盖“开单 → 预览 → PNG 生成”的桌面和手机视口几何对齐。
