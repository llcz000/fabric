# 运行与部署

## 统一图片资产运行

图片资产运行时由 IMAGE_ASSETS_ENABLED 总开关控制（需 MySQL）。业务开关 COMPANY_IMAGE_ASSETS_ENABLED / PRODUCT_IMAGE_ASSETS_ENABLED 为真时总开关必须为真，且要求 MySQL 可用。存储提供方由 ASSET_STORAGE_PROVIDER 显式选择（cos 或 local），绝不在单次请求失败时自动回退。完整环境变量、上传/迁移命令、回收与对账流程见 docs/solutions/architecture-patterns/image-asset-operations.md。

服务启用图片资产后会在启动时执行一次任务恢复（把 locked_at 超过 5 分钟的处理任务重置为 queued），并按周期运行 worker 循环与每日对账（重算引用计数、标记缺失对象为 degraded、枚举孤儿候选但不删除）。结构化日志经 observability.ts 脱敏，不输出 Cookie、密钥、签名原文。

## 环境要求

- Node.js：建议使用项目明确锁定的 LTS 版本。
- MySQL：生产推荐唯一权威数据源。
- 可选腾讯云 COS：用于产品图和上传文件。
- Python/OpenCV：仅 `generate_mockup.py` 工具需要，不是主应用运行依赖。

## 环境变量

| 键 | 是否必要 | 说明 |
|---|---|---|
| `ADMIN_PASSWORD` | 生产必须 | 管理密码；不得使用默认值 |
| `DB_HOST` | 推荐 | MySQL 主机 |
| `DB_USER` | 推荐 | MySQL 用户 |
| `DB_PASSWORD` | 推荐 | MySQL 密码 |
| `DB_DATABASE` | 推荐 | 数据库名 |
| `COS_SECRET_ID` | 可选 | COS 访问身份 |
| `COS_SECRET_KEY` | 可选 | COS 密钥 |
| `COS_REGION` | 可选 | COS 区域 |
| `COS_BUCKET` | 可选 | COS Bucket |
| `HOST` | 推荐 | 监听地址；直接对外监听通常使用 `0.0.0.0`，反向代理同机部署可使用 `127.0.0.1` |
| `PORT` | 推荐 | 服务端口，默认 `3000` |
| `RATE_LIMIT_WINDOW_MS` | 可选 | 限流窗口，默认 `900000`（15 分钟） |
| `API_RATE_LIMIT_MAX` | 可选 | 每客户端 IP、每窗口普通 API 上限，默认 `1000` |
| `LOGIN_RATE_LIMIT_MAX` | 可选 | 每客户端 IP、每窗口失败登录上限，默认 `10` |
| `NODE_ENV` | 生产必须 | `production` 使用 dist |
| `DISABLE_HMR` | 开发可选 | 控制 Vite HMR |

> [!danger] 密钥管理
> `.env` 不提交 Git；示例文件只放占位符。任何曾提交或落在文档中的真实密钥都必须轮换，单纯删除文件不够。

## 健康检查与停机

- `GET /api/health` 无需登录，仅返回 `status`、`storage`、`uptimeSeconds`。
- 生产负载均衡或进程守护应检查该端点，不要用登录页面作为健康判断。
- 服务收到 `SIGTERM`/`SIGINT` 后停止接收新请求，等待 HTTP 服务关闭并释放 MySQL 连接池。

## 反向代理与限流

- 健康检查不经过业务 API 限流。
- 登录与普通 API 使用独立额度；成功登录不消耗失败登录额度。
- 当前只信任 loopback 反向代理，适用于 Nginx 与 Node 部署在同一台主机。
- 直连应用端口的外部请求不能通过伪造 `X-Forwarded-For` 绕过客户端 IP 限流。
- 如果代理运行在 Docker、独立主机或 CDN，先明确代理网段，再修改 `trust proxy`；禁止无条件信任所有代理。

## 脚本注意事项

- 产品图片上传脚本已统一使用 `DB_*`。
- TIFF/JPG 路径硬编码在 `D:/tiff`、`D:/jpg`，应改命令行参数。
- 批处理脚本应先提供 dry-run，输出匹配/冲突报告后再写入。
